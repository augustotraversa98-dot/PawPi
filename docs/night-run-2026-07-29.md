## ⚡ NIGHT-RUN AUTONOMY PREAMBLE (applies to every N1–N10 ticket)

Tats is away. Operate fully autonomously, same rules as the Wave 5+ overnight runs:

- **Never ask questions / never stop for input.** Ambiguous choice → pick the most sensible, standard,
  on-brand option and proceed.
- **Merge policy:** one fresh branch off `origin/main` per ticket; CI green → squash-merge automatically;
  CI red → debug, fix, merge once green. Never leave a ticket half-done over a question.
- **Keep going down the queue** (build order below) for as long as tokens last. If the limit is reached,
  stop cleanly (no broken tree) and continue from the next ticket when the limit resets.
- **A ticket that turns out to be blocked on something only Tats can do (an account, a paid key, a
  business decision) is NOT a build failure.** Do the maximum code-side work possible, document exactly
  what's left and why in the PR body / the relevant doc, and move to the next ticket. Don't stall the
  queue waiting on something that will never come tonight.
- **Never touch files with known uncommitted Tats WIP** — `docs/app-store-connect-content.md` (§10 demo
  account) currently has unsaved edits per the 2026-07-29 handoff. Read it if useful context, don't write
  to it. If a ticket needs a change there, describe the needed edit in the PR body instead.
- **Update the bridge docs on every merge** — `docs/roadmap.md` + the `PawPi_instructions.md` status
  block, same commit or same PR as the work, per the sync rule in `docs/dev-pipeline.md`. This is the
  #1 lesson from the 2026-06-20→07-28 drift — don't repeat it.
- **No fake data, empty states only, RLS on every new table** — same house rules as always.

## What's genuinely NOT buildable tonight (and why)

Three things Tats flagged as unsure — verdict on each:

- **MercadoPago payment go-live.** The payment layer + MercadoPago/Binance adapters are already built
  (migration 0029, key-stubbed). What's missing is a real MercadoPago merchant OAuth app + a Binance Pay
  merchant account — those require Tats' business identity/bank details on MercadoPago's and Binance's
  own sites, not something Code can do. **N5** does everything code-side possible instead: harden the
  existing adapter, close test gaps, and turn `docs/test-backlog.md` ACTION 2 into an exact paste-ready
  setup checklist so account creation is the only remaining step.
- **Sign in with Apple.** Also already built and env-gated (ticket 2.46) — needs `AUTH_APPLE_ID` +
  `AUTH_APPLE_SECRET`, which come from registering a Services ID in Tats' Apple Developer account and
  downloading a private key. Code can't create that. **N6** does the code-side piece that's still
  genuinely useful: Apple's client-secret for Sign in with Apple is a JWT that expires (max ~6 months) —
  build it so it's generated/refreshed automatically from a stored key instead of becoming a recurring
  manual chore once Tats does the one-time key setup.
- **Apple Maps + address autofill.** This one IS mostly buildable tonight. The shared map component
  (ticket 2.68) already renders Apple Maps via `PROVIDER_DEFAULT` with **no paid key required**. What's
  missing is autofill: turning a dropped pin into a typed address, and a typed address into a pin. Both
  directions use on-device geocoding (`expo-location`'s `reverseGeocodeAsync` / `geocodeAsync`), which is
  free and already available — no new account, no new key. **N1** builds this.

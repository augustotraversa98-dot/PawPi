```
ORIENTATION
PawPi Expo mobile + web API (read). Phase-2 ticket 2.49: emotional memory + celebration loops that
compound the daily habit. Read docs/phase2-tickets/00-README.md.
AUTONOMY: don't ask; pick tasteful, on-brand designs and proceed. CI green → auto squash-merge; red → fix

Branch ticket/memories-wrapped. Gates: npm test (web vitest if you add a read; mobile jest).

CONTEXT
- The daily posts (BeReal) + pet birthday/adoption dates are the raw material. The 2.28 ShareableDailyCard

SCOPE
- On-this-day: a card/section surfacing past posts from the same calendar day (prior months/years) for

- Milestones: detect + celebrate Gotcha/adoption day + birthday (reuse 2.37 birthday logic), streak
  milestones (7/30/100 days), and a few activity milestones (e.g. Nth walk/post) — surface a tasteful
  celebration card when hit, shareable.
- Wrapped / Year in Review: an aggregated, multi-slide (or scrollable) recap for the active pet — total
  posts, walks, top moments, streak best, new friends, etc. — built from existing data, beautifully laid
  out, and EXPORTABLE/shareable as branded images (reuse + extend ShareableDailyCard). Pure aggregation
  helpers, tested.
- All sharing reuses the 2.28 flow (capture + system share sheet) with cute on-brand copy. Empty/young
  accounts degrade gracefully (no fabricated stats — show what exists or a friendly "not enough yet").
- Tests: pure aggregation helpers (on-this-day selection, milestone detection, wrapped tallies — TZ-aware,
  no false positives, empty-safe); render tests for the cards; the share handler invokes the share flow.

DO NOT: fabricate stats/memories when data is thin (empty-safe, no fake); build a second share path
(reuse 2.28); add a migration unless you genuinely need a new pet date column (check first). 

VERIFY: npm test green. PR body: on-this-day + milestones + Wrapped, all from real data, reusing the share
frame; empty-safe. DEVICE: see an on-this-day memory; hit a milestone card; open Wrapped and share a slide.
```

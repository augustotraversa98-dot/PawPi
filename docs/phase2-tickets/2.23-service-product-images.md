# 2.23 — Service & product image uploads

Read `00-README.md` first. Depends on: 2.1, the shop (2.11). **Recommended BEFORE 2.22** (storefront)
so services render with images; independent otherwise. Adds migration **0043** (`provider_services.image_urls[]`).
`shop_products` ALREADY has `image_urls[]` (0037) — this fills the gaps + wires upload UI.

```
ORIENTATION
PawPi web (provider dashboard) + Expo mobile (display). Phase-2 ticket 2.23: let providers upload images
for their SERVICES and PRODUCTS — "their store". Read docs/phase2-tickets/00-README.md.
Branch ticket/service-product-images off origin/main; squash-merge.
⚙️ NEW MIGRATION 0043 (provider_services.image_urls[] — additive; shop_products already has it). Gates:
npm test (web vitest + mobile jest) + npm run test:integration (provider_services RLS unchanged; prove
green). Confirm baselines first.

CONTEXT (read before editing)
- supabase/migrations/0014_providers.sql — provider_services (name, duration_min, price_cents, active …)
  has NO image column. Add image_urls text[].
- supabase/migrations/0037_shop_ecommerce.sql — shop_products.image_urls[] EXISTS. Just wire the upload +
  display (the column is there).
- The shared Supabase Storage upload path (used by health photos, report cards, etc.) + the web
  dashboard's services/locations and products screens (2.x / 2.11).

GOAL: a provider attaches one or more images to each service and each product from the web dashboard;
those images show on the storefront (2.22), the service menu, the shop catalog, and the booking/checkout
flows. Real uploads only, empty → a neutral placeholder (no fake product photos).

SCOPE
1. Migration 0043 — provider_services.image_urls text[] not null default '{}' (additive). No RLS change
   (provider_services already: published-provider public read, admin write). Document guard-unaffected.
2. Web dashboard: image upload (multi, via Storage) on the service editor and the product editor;
   reorder/remove; thumbnails. Persist image_urls through the existing service/product save routes
   (extend their whitelists to accept image_urls).
3. Display: render service images on the storefront service menu + booking form; product images already
   have a column — ensure the catalog/cart/checkout show them. Mobile shows the images where services/
   products render.
4. Validation: image_urls is an array of Storage URLs; cap a sane max count; reject non-array.
5. Tests: web vitest (service/product save persists image_urls; bad shape rejected); integration
   (provider_services RLS green with the new column — admin writes, public reads, non-staff can't write);
   mobile jest (images render where present, placeholder when empty).

DO NOT: add fake images; change provider_services / shop_products RLS; build a new upload path (reuse
Storage); break existing service/product save shapes (image_urls is additive + optional).

VERIFY: npm test (web+mobile) + integration green (baseline + net-new). PR body: the additive column
(0043), upload+display wiring, RLS unchanged. ⚙️ FLAG FOR TATS: apply 0043. DEVICE PASS: upload service +
product images on the dashboard → they appear on the storefront/catalog/booking; empty shows a clean
placeholder.
```

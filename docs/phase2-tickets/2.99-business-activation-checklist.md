## Context
The owner side gets an activation checklist in 2.98. A newly-onboarded business lands on the provider
dashboard (`apps/web/src/app/provider/`) with no guidance on the first high-value setup steps, so profiles
sit half-finished. All the pieces already exist (profile editor, services, products, locations/hours, posts)
— this ticket only adds a derived checklist surface over them.

## Current issue
Nothing nudges a new business to finish the setup that makes its storefront useful (profile, offerings,
hours, first post).

## Expected behavior
1. A **persistent "Getting started" card on the provider dashboard** (top of the main dashboard view),
   with a **% complete** progress indicator, visible until **100%**, then a brief success state and it
   retires. Derived — no manual dismiss.
2. **Checklist items** — each derived from real provider data, each linking to the existing screen:
   - **Complete your business profile** — logo + bio/description filled (tap → Profile).
   - **Add what you offer** — ≥1 service OR ≥1 product (tap → Services / Products).
   - **Set your hours / availability** — open hours or availability configured (tap → the relevant editor).
   - **Add a location** — ≥1 location/pin (tap → Locations).
   - **Share your first post** — ≥1 storefront post (tap → Storefront/Posts).
   `%` = completed ÷ total. Real derivation only (from the provider's capabilities/services/products/
   locations/hours/posts).
3. Clean, encouraging, on-brand (coral/cream) — a helpful setup guide, not a nag. Front-and-centre CTAs.

## Data / API rules
No migration. Completion derives from the provider's existing data (the same reads the dashboard already
makes for profile/services/products/locations/posts). If one aggregate read is cleaner, add a GET that
computes it from existing tables (no new table) and test it through the REAL router by URL; otherwise reuse
existing reads. Reuse every target screen — this ticket adds only the checklist surface.

## Acceptance criteria
- `npm test` (web vitest) green + baseline, plus tests: each item's derivation (done/undone), the `%` math,
  and the card hiding at 100%. Integration only if a new read/policy was added.
- DEVICE / dashboard pass: a freshly-created provider shows the checklist with correct progress; completing
  an item ticks it and bumps the %; at 100% it retires.
- Update `docs/roadmap.md` + `PawPi_instructions.md` status block + `docs/night-run-log.md`; add the Wave 11
  index entry to `00-README.md`.

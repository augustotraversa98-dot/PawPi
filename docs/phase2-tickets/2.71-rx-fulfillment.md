# 2.71 — Rx fulfillment: delivery / pickup + charging (Wave 7)

Read `00-README.md` (the ⚡ autonomy preamble + shared conventions) first. Web + mobile + migration. Bridges
the vet Rx (2.53) → shop/e-commerce (2.11) → payments (2.3): a vet-issued prescription becomes a fulfillable
order a provider dispenses (delivery or pickup) and the owner pays for. STRICT medical-adjacent RLS — the
clinical Rx stays owner-read-only/append-only (2.53); fulfillment NEVER lets the owner forge or edit an Rx.
Reuse shop orders + payments; do NOT rebuild them.

```

CONTEXT
- 2.53 built prescriptions (owner READ-ONLY, append-only; vet issues; refills decremented ONLY via the
  decide_rx_refill DEFINER) + rx_refill_requests. The master plan's `pharmacy` provider_type = "Rx
  validation against vet records (consent), refills" — fulfillment is the missing piece.
- The dispensing party is a provider with a fulfillment capability. Decision: add a `pharmacy` capability
  (widen the capability CHECK additively, the drop+re-add pattern 0040/0054 used). A clinic that both
  prescribes and dispenses simply holds BOTH `vet` and `pharmacy`. (A vet issues the Rx via 2.53; a
  `pharmacy`-capable provider fulfills it — same business or a different one the owner chooses.)
- Shop e-commerce (2.11) already has products/orders/order_items + checkout via payments (2.3, degrades
  cleanly to "payments not configured"). Reuse the order + payment rails — a fulfillment IS an order with a
  link back to the prescription; do NOT build a parallel order/payment system.
- Owner consent + Rx ownership gate everything: a fulfillment can only be created for an Rx the requesting
  owner actually owns and that has remaining refills; the dispensing provider sees only what it's fulfilling.

GOAL
From an active prescription in their Vet Record, an owner requests fulfillment: choose a `pharmacy`-capable
provider, choose delivery (address via the 2.68 map) or pickup (provider location), see the price, pay via
payments (2.3), and track status (requested → accepted → preparing → ready/out_for_delivery → fulfilled /
cancelled). The provider sees incoming Rx fulfillment orders, sets price, and advances status; fulfilling a
refill decrements refills via the EXISTING 2.53 safe path (never a raw write). Real data + empty states.
```

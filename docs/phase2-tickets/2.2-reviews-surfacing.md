# 2.2 — Reviews & ratings surfacing

Read `00-README.md` + `../phase2-superapp-master-plan.md` §2 first.

```
ORIENTATION
PawPi web API + mobile. Phase-2 ticket 2.2: surface the EXISTING provider_reviews table (created in
0014, never wired). Read docs/phase2-tickets/00-README.md, the master plan §2, 0014_providers.sql
(provider_reviews: owner_user_id, provider_id, pet_id?, rating, body...), the booking routes
(api/providers/[id]/book, /bookings) to scope "review after completed booking", discovery/public routes
(to show ratings), and the RLS pattern (provider_reviews already has a policy from R2e — verify it).
Branch ticket/reviews-surfacing off origin/main; squash-merge; migration only if a column/aggregate
needs adding. Gates: npm test + (if DB) npm run test:integration.

GOAL: owners write a review after a completed booking; aggregate rating + count show on discovery cards
and the public provider profile; provider sees their reviews.

SCOPE (web API)
- POST /api/providers/[id]/reviews — owner writes a review. Gate: the owner must have a COMPLETED
  booking/order with this provider (look it up); one review per completed booking (dedup). Fields:
  rating 1–5, body, optional pet_id. owner_user_id from session.
- GET /api/providers/[id]/reviews — list a provider's reviews (public-ish: any authed; show reviewer
  display name + pet, rating, body, date). Paginated.
- Aggregate: add avg_rating + review_count to the discovery (/discover) + public/[slug] responses
  (computed via JOIN/aggregate over provider_reviews; or a cached column updated on write — your call,
  document). 
- RLS: confirm/adjust provider_reviews policies — SELECT public for a published provider's reviews;
  INSERT owner-only (owner_user_id = current_app_user_id()) + the completed-booking precondition is
  app-layer; UPDATE/DELETE own review only. Harness proof if you touch the table.
- Vitest: review write requires a completed booking (else 403/400); one-per-booking dedup; aggregate
  appears in discovery/public; cross-user can't write/edit another's review.

SCOPE (mobile)
- Show rating + count on the vet discovery cards + provider profile screen; a "Write a review" entry
  after a completed appointment (reuse the booking/appointment surface). Real data, empty states.

DO NOT: allow reviews without a completed booking; let a provider edit/delete reviews; fake ratings.

VERIFY: npm test + integration green (baseline + net-new). PR body: review-after-completed-booking
rule, aggregate surfacing, RLS. Confirm origin/main before next.
```

# 2.64 — Double-tap an image to give it a Paw (like) in the brand color

Read `00-README.md` (Wave 6 order + the ⚡ autonomy preamble) first. Mobile only. NO migration. Reuses the
existing paw endpoint. Touches Feed image components — sequence with the other Feed tickets.

```
ORIENTATION
Read ARCHITECTURE.md and supabase/SCHEMA_NOTES.md to get oriented, then this task. PawPi Expo mobile app.
Phase-2 ticket 2.64: double-tap (and double-click) on a post image gives it a Paw — the app's "like" —
with a brand-color paw animation, like Instagram's double-tap heart. Read docs/phase2-tickets/00-README.md
(autonomy preamble; warm/coral design).
AUTONOMY: don't ask; pick the sensible option and proceed. CI green → auto squash-merge; red → fix then
merge. One fresh branch off origin/main: ticket/double-tap-paw.
Gates: npm test (mobile jest).

CONTEXT
- A Paw is the existing "like" on a post. The endpoint exists: app/api/posts/[id]/paw/route.js (web), and
  the paw button already works in the feed / post detail. The paw count shows on cards + the daily-moments
  grid (e.g. the "0" / "1" paw badges in Tats's screenshot).
- Post images render in components/Feed/PostCard.jsx and components/Feed/PostDetailModal.jsx.
- Brand color = coral (COLORS.coral / the app's primary). The paw glyph (PawPrint) is already used.

GOAL
Double-tapping a post image gives it a Paw (idempotent — a second double-tap does not stack; it's a like,
not a counter you can spam) with a quick brand-color paw "pop" animation over the image, and the paw count/
state updates to reflect it. Works in the feed and in the post detail. The existing single-tap paw button
stays and stays in sync (double-tap and the button reflect the same state).

SCOPE
- Add a double-tap gesture to the post image (PostCard + PostDetailModal). On double-tap: if not already
  pawed, call the paw endpoint (optimistic) and play a brief paw-pop animation (the PawPrint in
  COLORS.coral, scale/fade) centered on the image; if already pawed, just replay the little animation (do
  NOT unpaw on double-tap — Instagram-style). Keep the existing paw button as the explicit toggle
  (paw/unpaw).
- Keep state in sync: the button, the animation, and the count all reflect the same pawed state; revert
  optimistic update on error.
- Don't interfere with other gestures: a single tap on a feed image should still open the post detail (or
  its current behavior); only a DOUBLE tap paws. Use a gesture that disambiguates single vs double cleanly.
- Tests: mobile jest (double-tap on an un-pawed image calls the paw endpoint once + sets pawed + triggers
  the animation; double-tap on an already-pawed image replays the animation WITHOUT a second paw call and
  without unpawing; the paw button stays in sync; optimistic revert on error; single-tap behavior
  unchanged).

DO NOT: unpaw on double-tap (only the button toggles off); double-count / spam the endpoint on repeated
double-taps; break single-tap navigation; use a non-brand color for the animation; add fake paw counts.

VERIFY: npm test green. PR body: the double-tap gesture + the brand-color paw-pop animation + the
optimistic paw with revert + the button/count sync. DEVICE: double-tap a feed image → a coral paw pops and
the post is pawed (count +1); double-tap again → the paw animates but the count doesn't change and it stays
pawed; the paw button reflects it; tapping the button still toggles paw/unpaw; single-tap still opens the
post.
```

# 2.13 — Feed integration (businesses/services in the social feed)

Read `00-README.md` + `../phase2-superapp-master-plan.md` (§2) first. Depends on: 2.1 (capabilities),
ideally some live services + 2.2 (reviews) for richer cards.

```
ORIENTATION
PawPi web API + mobile. Phase-2 ticket 2.13: surface providers/services in the social feed for organic
discovery alongside pet posts. Read docs/phase2-tickets/00-README.md + master plan §2. Read the feed
implementation (api/posts GET — Following + Suggested merge; the mobile useFeedPosts + PostCard) so
provider cards interleave cleanly without breaking the BeReal daily-lock or the existing post shapes.
Branch ticket/feed-providers off origin/main; squash-merge; migration only if a promotions table is
added. Gates: npm test + (mobile) jest + (if DB) integration.

GOAL: occasionally surface relevant published providers/services (and adoptable dogs) as distinct
"discover this business / adopt this dog" cards in the feed, location/capability-relevant, without
spamming or breaking the social feed.

SCOPE
- Decide the surfacing model (document): inject provider/service "suggestion" cards into the feed at a
  controlled cadence (e.g., every N posts), sourced from published providers (discovery) +
  optionally adoptable listings (2.12) — relevant by capability/location/rating (2.2). Keep it a
  SEPARATE card type from pet posts; never fake a pet post.
- API: extend the feed response (or a sibling endpoint) to return interleaved provider/adoption
  suggestion items with a clear type discriminator + the public fields only (no owner/medical/staff
  data). Respect existing pagination + mergeFeed; don't disturb Following/Suggested post logic or the
  BeReal lock.
- mobile: a ProviderFeedCard / AdoptionFeedCard rendered inline (tap → provider profile / adoption
  listing). Clearly distinct visual from PostCard.
- Tests: feed returns interleaved provider/adoption cards with the discriminator; cadence/cap; no
  owner/medical leak in the payload; existing post tests unchanged.

DO NOT: leak any private/owner/medical data into feed cards; break the BeReal lock or feed ordering;
disguise ads as pet posts; over-inject (cap the cadence). No fake providers.

VERIFY: npm test + jest + (if DB) integration green (baseline + net-new). PR body: surfacing model +
cadence, the distinct card type, the no-leak assertion. Confirm origin/main.
```

# 2.83 — Mobile "magic onboarding" wizard (Wave 9, ⛔ after 2.81 + 2.82)

**Status:** BUILT — CI-green. No migration. Reuses 2.20/2.21/2.82 endpoints + existing save routes.

## Goal
The fastest possible mobile business onboarding: the provider gives a little, the system pre-fills
the rest, they only adjust. Confirm-first — nothing publishes until they save.

## Flow (mobile, `app/vet-business-access.jsx`)
1. Pick service type(s) — existing multi-select (2.15).
2. Drop the map pin — shared `LocationField` (2.81).
3. Paste links (website / IG / FB / Maps) (2.20) + optionally upload a price-list document
   (`expo-document-picker` → shared Storage upload) (2.82).
4. Tap **"Build my profile ✨"** → creates the provider draft + its primary location, then calls the
   confirm-first enrichment: `/enrich` (links + Google Place) and, if a document was uploaded,
   `/enrich/document`. Both write NOTHING.
5. If the merged draft proposes anything (a description or candidate services) → ONE **confirm-first
   review screen**: editable description + proposed services (toggle off / edit name/price/duration)
   + a candidate-photos note. On **Save & finish** the description applies via the provider PATCH
   (`bio`) and each selected service via the existing services CRUD (`POST .../services`).
6. If enrichment is unconfigured (keyless) or proposes nothing → straight to the created-business
   success state (fully manual, no dead ends).

New mobile hooks (`useProviders.js`): `useEnrichProvider`, `useEnrichProviderDocument`,
`useUpdateProvider`, `useCreateProviderService`. Pure draft→CRUD mapping in
`utils/enrichmentDraft.js` (price/duration parsing; no fake data — unparseable → null/omitted).

## Data
No new table. Reuses 2.20/2.21/2.82 endpoints + the existing owner-identity save routes
(`POST /api/providers`, `POST .../locations`, `PATCH /api/providers/[id]`, `POST .../services`).
IG/FB are links-only (never scraped).

## Degrade-clean
No enrichment keys → `/enrich` + `/enrich/document` 503 → caught → empty draft → manual onboarding,
identical to before. A failed location/service write never blocks the business from being created.

## Acceptance ✅
End-to-end on mobile: links + pin + document → pre-filled review → edited → saved (real rows);
empty/keyless path degrades to manual with no dead ends; IG/FB links-only; mobile tests green.

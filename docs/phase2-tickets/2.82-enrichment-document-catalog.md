# 2.82 — Enrichment: build a service/product catalog from an uploaded document (Wave 9)

**Status:** BUILT — CI-green. No migration. Reuses `ENRICHMENT_LLM_KEY` (already on the go-live list).

## Goal
Add **documents** as a third enrichment source (after website + Google Place, 2.21). A provider
uploads a PDF or Excel/CSV price-list/menu and the system PROPOSES a structured
`{ services, products }` catalog they review and edit. Confirm-first: the `/enrich` path writes
nothing.

## What shipped
- **`api/utils/enrichment/document.js`** — `fetchDocumentCatalog(file)`:
  - **Tabular (CSV / XLSX):** parsed to rows (papaparse / SheetJS), then mapped to a catalog by
    plain header heuristics (`name`/`title`/`item`/`service`/`product`, `price`/`cost`/`fee`,
    `duration`/`mins`, `description`/`notes`). A row with a duration reads as a **service**, else a
    **product**. Works with **no LLM key** ("return only what plain parsing found").
  - **Text (PDF):** parsed to raw text, then STRUCTURED by the LLM (behind `ENRICHMENT_LLM_KEY`).
    The default text structurer is a **dormant placeholder** (mirrors the website source) — proposes
    nothing rather than inventing data until a real LLM adapter is injected/wired.
  - Heavy parsers are **lazy-imported** (so CI never loads them; tests inject mock extractors). Every
    parse **fails soft** — a malformed/unreadable file returns an empty draft, never throws.
- **`POST /api/providers/[id]/enrich/document`** — owner|admin. The client uploads the file through
  the existing Storage path (transient input) and passes `{ url, filename, mimeType }`. Dormant
  behind `ENRICHMENT_LLM_KEY` → clean 503 when unset. Returns `{ draft, sources, applied:false }`.
  Makes **no INSERT/UPDATE** (only the `resolveUserId` SELECT).
- **`DocumentCatalogImport` panel** (Services dashboard) — upload → propose → edit each proposed row
  → **Apply** (routes through the existing `useCreateService` / `useCreateShopProduct` CRUD) / **Skip**.

## Data
No new table, no migration. Adds `xlsx@0.18.5` (SheetJS, lazy-loaded) for XLSX parsing.

## Acceptance ✅
A mocked PDF (via injected LLM) and a mocked XLSX each yield a proposed catalog draft; missing key →
clean "not set up yet"; the route asserts no direct INSERT/UPDATE on providers/services; a malformed
file fails soft (empty draft, no throw to client); web tests green.

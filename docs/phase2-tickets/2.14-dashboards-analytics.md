# 2.14 — Dashboards & analytics (provider + owner hubs)

Read `00-README.md` + `../phase2-superapp-master-plan.md` (§2) first. Depends on: the services +
payments (2.3) + bookings (2.4) + reviews (2.2) producing data to chart. Do near the end of Phase 2.

```
ORIENTATION
PawPi web (provider dashboard) + mobile (owner). Phase-2 ticket 2.14: analytics/overview hubs. Read
docs/phase2-tickets/00-README.md + master plan §2. Provider dashboard is anything/apps/web/src/app/
provider/ (recharts is already a web dep). Aggregate ONLY over data the provider/owner already may see
(reuse the RLS-scoped routes; no new cross-boundary reads). Read the existing provider shell + the
bookings/orders/reviews/payments routes to source metrics.
Branch ticket/dashboards-analytics off origin/main; squash-merge; usually NO migration (read-only
aggregates) — add a summary endpoint if needed. Gates: npm test + (if DB) integration.

GOAL: a provider sees their business at a glance; an owner has a unified hub of their bookings/orders/
access.

SCOPE
- Provider dashboard home: revenue (from payments/payouts, 2.3), bookings over time + upcoming
  (2.4), occupancy (daycare), reviews/avg rating (2.2), top services. recharts visuals. All scoped to
  the active provider via the existing staff-membership + RLS — a summary/analytics endpoint that only
  aggregates the provider's own rows.
- Owner hub (mobile): "My bookings" (upcoming/past across all services), "My orders" (shop, 2.11),
  "Who has access" (existing care-access grants), subscriptions (2.3), saved/favorited providers +
  adoption listings. A single place tying the super-app together.
- Analytics endpoint(s): aggregate over RLS-scoped data only; no raw cross-user reads. Vitest +
  (if a new endpoint touches DB) integration that it never returns another provider's/owner's data.

DO NOT: aggregate across providers/owners (no cross-boundary reads); add heavy BI infra; duplicate the
per-feature screens (this is an overview that links into them). No fake metrics.

VERIFY: npm test + (if DB) integration green. PR body: the metrics shown, the RLS-scoped aggregation
(no cross-boundary leak), recharts usage. Confirm origin/main.

NOTE: this is also where the deferred ANALYTICS/ANONYMIZED-PREDICTIONS layer (separate read-only role +
true anonymization + opt-in consent — see PawPi_instructions.md) stays OUT of scope: this ticket is
per-provider/per-owner operational analytics only, on the live RLS-scoped path.
```

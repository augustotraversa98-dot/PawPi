THE BUG
- Create a new pet (or switch the active pet) → go to More → the top (orange) area still shows the
  PREVIOUS pet's name. It should reflect the currently-active pet.

CONTEXT
- The active pet comes from the single useCurrentPet (in apps/mobile/src/hooks/usePetProfile.js) +
  persisted selection (pawpi:selectedPetId). The header that shows the pet name is on the More landing
  (apps/mobile/src/app/(tabs)/more/index.jsx) — find the component rendering the name.
- Likely cause: the header reads a stale value (cached/local state) instead of the reactive current-pet,
  or doesn't re-render on switch/create, or the React Query key isn't invalidated after add/switch.

GOAL: the More header always shows the currently-active pet's name + avatar, updating immediately on pet
switch and on new-pet creation.

SCOPE
- Make the header read the reactive current pet from useCurrentPet and re-render on change. Ensure
  add-pet and switch-pet invalidate/refetch the relevant queries (['pets'] / current-pet) so the header
  updates without an app restart.
- Tests: switching the active pet updates the rendered header name (mock the hook/store; assert re-render).

DO NOT: introduce a second source of current-pet truth (use the single useCurrentPet); add a migration.

VERIFY: npm test (mobile) green. DEVICE: create/switch a pet → More header shows the new pet immediately.

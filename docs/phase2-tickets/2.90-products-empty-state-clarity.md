# 2.90 — Products section: replace the "shop capability" jargon with a clear enable + add-first-product flow

**Status:** ready · no migration · ⛔ after 2.89 (shared provider offerings/nav surfaces) · safe-parallel:
no (touches the same offering-toggle 2.89 wires)

## Context
The store is the `shop` capability + `shop_products` (migration 0037, has `image_urls[]`); the provider
dashboard renders a Products section. Real product image upload already exists (ticket 2.23 shared
`ImageUploader` + Storage path). This ticket is a UX/clarity pass, not new storage.

## Current issue
When a business doesn't have the store enabled, the Products area shows a message like **"This business
doesn't have the shop capability."** — meaningless to a business owner ("capability" is internal jargon,
and it gives no way forward). More broadly, adding and showing products should be obvious and fast.

## Expected behavior
1. **Not-enabled state.** If the business hasn't enabled the store yet, replace the jargon message with a
   friendly explanation of what Products is (selling items to pet owners) and ONE clear button that enables
   it — flipping the same `shop` offering the Business Profile controls (reuse the 2.89 offering toggle /
   the existing profile write path, do not fork a new one) — and drops the business straight into adding
   its first product.
2. **Enabled-but-empty state.** If the store is enabled but has no products, show an inviting "Add your
   first product" state with the add action front-and-center (not an error, not a blank page).
3. **Populated state.** Adding a product is fast and obvious: name, price, description, and images (reuse
   the existing `ImageUploader` + Storage path from 2.23 — do not build a new upload path). Products the
   business added render clearly with their images.
4. **No internal jargon anywhere in user-facing copy** — no "capability", "storefront key", etc., in EN or
   ES. Plain language a pet-shop owner understands.

## Data / API rules
No migration. Reuses `shop_products` (0037) + the existing product save/image routes and the `shop`
capability toggle from the profile. No RLS change (reuse the existing provider-admin write / public read).
If you touch a read policy, prove it in the integration harness.

## Acceptance criteria
- `npm test` (web vitest) green + baseline; integration only if a policy changed.
- Web tests: the not-enabled state renders the enable CTA and clicking it flips the `shop` offering on and
  routes to add-product; the enabled-empty state renders the add-first-product CTA; a saved product renders
  with its image.
- Grep the diff to confirm no user-facing string contains internal jargon ("capability", etc.).
- DEVICE / dashboard pass: as a business with no store → see the friendly enable prompt (not the old
  message) → enable → land on add-product → add one with an image → it shows in the catalog; empty state is
  inviting, not an error.
- Update `docs/roadmap.md` + `PawPi_instructions.md` status block + `docs/night-run-log.md` on merge.

## Context
The pet-owner social profile (`apps/mobile/src/app/pet-profile.jsx`) is the design target: a rich header
(avatar, name, @handle, breed·age, "with <owner>"), a stat row (Daily posts · Paws · Barks · Followers ·
Following), and a "Daily moments" IMAGE GRID whose tiles open a post you can view full-size and engage
with. The business storefront (`apps/mobile/src/app/service/provider.jsx`) instead renders a plain
StoreHeader (name + rating) and a Posts tab (`components/Providers/StorefrontPanels/PostsPanel.jsx`) that is
a text + single-thumbnail card list. Post detail already exists (`service/provider-post.jsx`, shipped) and
comments exist (migration 0082). Businesses have followers (the follow endpoint returns `followersCount`).

## Current issue
The business Posts experience looks nothing like the pet profile (compare on device): no @handle, no info
line, no stat row, images don't open into a viewer, and posts read as a flat list rather than a grid.

## Expected behavior
Bring the business storefront header + Posts to visual parity with the pet social profile, REUSING the
pet-profile header / stat-row / moments-grid components and patterns (don't hand-roll a parallel design):
1. **Header:** business name on top with an **@handle** (reuse the provider `slug` → `@{slug}`) and an
   **info line** (the provider's existing bio/tagline/description). Keep the logo/cover already shown.
2. **Stat row** styled like the pet profile, with the four stats requested: **Posts** (count of this
   provider's posts), **Paws** (total likes across its posts), **Barks** (total comments across its posts,
   from 0082), **Followers** (from the follow endpoint's `followersCount`). Omit "Following" (a business
   doesn't follow). Real counts only. NOTE: the Paws primitive is added in ticket **2.94** — until then,
   render the Paws slot from a paw-count source that DEGRADES to 0 (never crash); 2.94 lights it up.
3. **Posts as an image grid** (moments-style): show the uploaded images as grid tiles (not one small
   thumbnail). Tapping a tile opens the post detail (`provider-post.jsx`) where images display full-size, a
   guest/owner can READ, and a signed-in owner can COMMENT (existing flow). Images must open/enlarge.
4. Guests view + read; commenting stays gated to signed-in owners (unchanged). EN + ES, neutral "tú".

## Data / API rules
No migration. Reuse the provider public profile (name/slug/bio/posts), the follower count, and the 0082
comment counts (add a lightweight per-provider comment/post count to the profile payload if not already
present — a read; prove any new read policy in the integration harness, else reuse existing reads). The Paws
count source is wired here but produced by 2.94 — treat a missing paw table as 0.

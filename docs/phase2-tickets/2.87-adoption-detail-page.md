# 2.87 — Adoption detail page (rich profile) (Wave 9, ⛔ after 2.85)

**Status:** BUILT — CI-green. No migration.

## Goal
Tapping a browse card (2.86) opens a full, rich profile (reference depth: nolimitpets.org welfare
page) — media gallery + facts + story + compatibility + shelter map + Apply/Foster CTA.

## What shipped
- **Backend (no migration):** extended the public single-listing GET (2.56,
  `GET /api/providers/[id]/adoptable-listings/[listingId]`) to also return the shelter's **primary
  location** (`provider_lat/lng/address/name`, via a LEFT JOIN LATERAL — same shape as the 2.86 browse
  row), so the detail has everything in one call whether opened from browse or a deep-link.
- **Mobile (`app/service/adoption.jsx`), `DogProfileDetail` rewritten:**
  - **Media gallery** (`MediaGallery`): all `photo_urls[]` as a swipeable paged carousel + the
    `video_url` as a final page (`expo-av` `Video`, native controls) + page dots. Empty → paw
    placeholder (no fake media).
  - **Key facts grid** (age, gender, size, breed, vaccination, fee) — each fact renders only when the
    value is real; unknowns are omitted, never shown as fake.
  - **Compatibility chips** (energy + good-with kids/cats/dogs).
  - **Story** section.
  - **Shelter card** with name + address + a `MapLocationView` (2.68) pin when coords are known
    (omitted cleanly when not).
  - **CTA** unchanged: Apply to adopt / foster (reuses the existing `adoption_applications` flow +
    the 2.57 placement picker), chat, fee/donation. The 2.30/2.56 deep-link still lands here.

## Acceptance ✅
Opens the exact tapped listing; gallery swipes photos + plays the video; only real fields render
(unknown facts + the map omitted when absent); the shelter map shows when coords exist; Apply/Foster
opens the existing application flow; the feed/discovery deep-link lands here; tests green.

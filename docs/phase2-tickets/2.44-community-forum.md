SCOPE

  test-backlog ACTION 1.

  Keep score updates safe (a SECURITY DEFINER vote helper or a transactional upsert — pick the simpler
  that stays RLS-correct).
- Mobile: category list → thread list (sortable) → thread detail with comments + reply + vote; compose a
  thread (title/body/image). Remove the COMMUNITY_POSTS mock usage. Empty states.
- Tests: web vitest (create thread/comment, vote idempotency + score, sort orders, author-only edit);
  integration (any-authed read, author-only write/delete, one-vote-per-user RLS proofs); mobile jest
  (browse/compose/comment/vote render + empty states; mock removed).

DO NOT: keep mock community data as a fallback; allow editing/deleting others' content; allow double-
voting; add fake threads. Migration hand-applied by Tats — flag it.

VERIFY: npm test + integration green. DEVICE: create a thread, comment, upvote; sorts work; another
account sees it; empty category shows an empty state.

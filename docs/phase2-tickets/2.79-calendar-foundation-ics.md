# 2.79 — Calendar foundation: unified calendar layer + ICS export (Wave 8)

Read `00-README.md` (the ⚡ autonomy preamble + shared conventions) first. Mobile refactor + web API. **NO
migration.** This is the FOUNDATION of Wave 8 calendar integration — **build it FIRST**; 2.80 wires every
remaining scheduled surface onto it. Add-to-device calendar ALREADY exists, but only for **walks** + **vet
appointments**, via two near-duplicate blocks in `calendarIntegration.js`. Unify them into one generic layer,
keep the existing wrappers + call-sites working unchanged, add CI-runnable tests for the pure logic, and add a
web **ICS-export** route so calendar works cross-platform and is actually testable in CI (expo-calendar native
calls can't run in CI).

```
ORIENTATION
Read ARCHITECTURE.md and supabase/SCHEMA_NOTES.md to get oriented, then this task. PawPi Expo mobile + web
API. Wave-8 ticket 2.79: unify the calendar-integration util + add an ICS export route. Read
docs/phase2-tickets/00-README.md (shared conventions; the ⚡ autonomy preamble applies). No prereq — this is
the Wave 8 foundation (2.80 depends on it).
AUTONOMY: don't ask; pick the sensible, on-brand option and proceed. CI green → auto squash-merge; red → fix
then merge. One fresh branch off origin/main: ticket/calendar-foundation.
Gates: npm test (web vitest + mobile jest); npm run test:integration (real-Postgres RLS). NO new table/column
this ticket — the only DB touch is the new ICS route reading the caller's own vet_appointments (read-only,
owner-scoped); completeness guard must stay green/unaffected.

CONTEXT
- expo-calendar (~15.0.8) is ALREADY a dependency. anything/apps/mobile/src/utils/calendarIntegration.js
  already implements: requestCalendarPermission, isCalendarAvailable, addWalkToCalendar (+ getWalkEvents,
  formatFrequency), addVetAppointmentToCalendar / updateVetAppointmentInCalendar /
  deleteVetAppointmentFromCalendar. It contains TWO near-identical private getters —
  getSocialPetCalendar ("Social Pet - Walks") and getVetAppointmentsCalendar ("Social Pet - Vet
  Appointments") — that duplication is the main thing to remove.
- Call sites that MUST keep working with ZERO behavior change (same exported names, signatures, return
  shapes): WalkItem.jsx, WalkCountdownCard.jsx, RoutineCard.jsx, and VetAppointmentRoutineModal.jsx (the
  last persists the returned eventId into vet_appointments.calendar_event_id and update/deletes it on edit/
  cancel). Return shapes today: addWalkToCalendar → boolean; addVetAppointmentToCalendar → { success,
  eventId }; update/delete → { success, error? }. Preserve all of these exactly.
- The booking spine is vet_appointments: every booking (grooming/walking/daycare/sitting/transport/
  telehealth) is a vet_appointments row and ALREADY has a calendar_event_id column (migration 0005). So the
  booking surfaces 2.80 will wire need NO new column. Community events (0060) are the exception and are
  handled in 2.80 — not here.

GOAL
One generic, de-duplicated calendar layer in calendarIntegration.js, with the existing walk + vet functions
reduced to thin wrappers (zero behavior change at every call site). The pure mapping/formatting logic lives
in its own expo-free module covered by jest. Plus a web ICS-export endpoint so an owner can download/share a
booking as a standard .ics (opens in Apple/Google Calendar, works on Android/desktop/email) — which also
gives the foundation real CI coverage.

SCOPE
- Mobile refactor (calendarIntegration.js): extract a single getOrCreatePawPiCalendar({ title, color, name })
  that de-dupes the two getters, plus generic upsertCalendarEvent(calendarId, details, existingEventId?) and
  deleteCalendarEvent(eventId). Rewrite addWalkToCalendar + addVetAppointmentToCalendar / update / delete as
  thin wrappers over them. KEEP every current exported name, signature, and return shape so NO call site
  changes. Preserve the existing behavior: BUSY availability, iOS PRIVATE accessLevel, the permission
  rationale alert, the per-feature calendar titles/colors, and graceful failure.
- Extract the PURE helpers into a separately-testable module with NO expo-calendar import, e.g.
  src/utils/calendarFormat.js: getRecurrenceRule (frequency → DAILY/WEEKLY+daysOfTheWeek/MONTHLY mapping),
  parseWalkTime, formatFrequency, and a buildEventNotes(kind, data) for the walk/vet notes strings.
  calendarIntegration.js imports these. This module is what jest covers (the native Calendar calls stay
  mocked/untested).
- Web ICS route (server-side, owner-scoped, holds NO secret): GET /api/calendar/booking/[id].ics → look up
  the vet_appointments row for the signed-in owner (owner_user_id = current user); 404/empty if it isn't
  theirs; return a valid single-VEVENT text/calendar payload — stable UID per booking, DTSTART/DTEND from
  appointment_date + appointment_time + duration, SUMMARY/LOCATION/DESCRIPTION from title/clinic/reason,
  text escaped per RFC 5545 (commas, semicolons, newlines), CRLF line endings. Auth-gated; never returns
  another owner's booking. (The events ICS route comes in 2.80.)
- i18n: any new user-facing strings via t() EN+ES (the refactor should add few/none).
- Tests: mobile jest — calendarFormat pure helpers (daily / weekly-with-days / monthly recurrence mapping,
  time parse, notes builder, formatFrequency) + a mocked-expo-calendar smoke that the wrappers still return
  their documented shapes. web vitest — the ICS route builds a spec-valid VEVENT from a mocked booking row,
  escapes special chars, is auth-gated, and returns a clean 404/empty for a non-owner (never another owner's
  data). integration — the ICS route reads only the caller's vet_appointments as pawpi_app (owner sees own,
  other owner gets nothing); no new table; completeness guard green/unaffected.

DO NOT: change any existing call site's behavior or exported names (this is a pure internal de-dup); add a
migration or any new table/column this ticket; ship secrets to the client (the ICS route is server-side and
holds no key); invent fake/sample events; break the existing walk/vet calendar flows; use a non-Apple
map/calendar on iOS.

VERIFY: npm test + integration green; completeness guard green (unchanged). PR body: the de-duplicated
calendar layer (one getter + generic upsert/delete), the extracted pure calendarFormat module + its jest
coverage, the unchanged walk/vet wrappers + call sites, and the owner-scoped ICS booking route + its tests.
DEVICE: existing "Add to calendar" on a walk and on a vet appointment still work exactly as before (add, and
for the vet appointment edit/delete round-trips); downloading a booking .ics from web opens cleanly in
Apple/Google Calendar.
```

GOAL
On a pet's social profile, tapping Followers opens the list of pets that follow this pet; tapping Following
opens the pets this pet follows. Each list: a quick type-to-search filter; each row shows the pet
(photo + name + @handle) and a follow-state button — a "Follow" affordance with the PAW icon when the
viewing pet does NOT follow them, and a "Following" state when it does; tapping it follows/unfollows
(optimistic, persisted). Tapping the pet (photo/name) opens that pet's social profile. Real data + empty
states ("No followers yet" / "Not following anyone yet" / "No matches").

  route with a ?rel= param) returning the list of pets (public fields only) + for each, whether the

  Paginate if needed. Reuse the existing follow endpoint for the toggle. No private/medical fields.

  needs a predicate over another table, add it within the existing public-read posture — do NOT loosen

- Mobile: make the Followers / Following counts on pet-profile.jsx tappable → a Followers/Following list
  screen (route through the root-level service/ or an appropriate stack so the 2.19 nav isn't corrupted)
  with: a search field that filters live by name/@handle; rows with avatar (2.55 fallback) + name +
  @handle + the paw Follow / Following toggle (optimistic update, calls the follow endpoint, reverts on
  error); tapping a row opens that pet's profile. Empty + no-match states.
- Tests: web vitest (followers/following return public fields only + the follows-state flag; no leakage;

  opens the profile; empty/no-match states).

corrupt the More/profile nav (route correctly per 2.19); show fake followers; let the toggle update only
local state (must persist + refetch/optimistic-with-revert); allow following yourself.

VERIFY: npm test (+ integration if a policy changed) green. PR body: the followers/following read routes

pet (paw) → it flips to Following and persists across reopen; unfollow flips back; tap a pet → its profile;
empty/no-match states show; you can't follow yourself.

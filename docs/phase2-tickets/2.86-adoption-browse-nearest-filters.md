# 2.86 — Adoption browse: gallery, nearest-first, filters, redesigned card (Wave 9, ⛔ after 2.85)

**Status:** BUILT — CI-green. No migration (read-only over existing tables).

## Goal
Replace the per-shelter grouped browse with a single responsive grid of adoptable dogs, photo-on-top /
info-below (the pet is fully visible, not overlaid), sorted **nearest-first**, with composable filters.

## What shipped
- **New owner-facing endpoint** `GET /api/adoption/listings` — one flat read across every PUBLISHED
  shelter's AVAILABLE dogs, joined to the provider + its **primary location lat/lng** (from 2.81).
  Visibility reuses the discovery rule (rides 0038 listing public-read + 0024 provider_locations
  public-read for published providers). Composable filters: `gender`, `size`, `age_min/age_max`,
  `energy_level`, `good_with_kids/cats/dogs`, `vaccination_status`, `provider_id`, and location
  (`lat`+`lng`+`radius_km` bounding box) or `city`. **Nearest-first** (haversine, distance attached)
  when lat/lng are valid; else featured-then-recent. No migration.
- **Mobile browse redesign** (`app/service/adoption.jsx`): the Browse tab now requests the device
  location (`expo-location`, graceful deny), calls `useAdoptableBrowse(filters)`, and renders a
  2-column grid of the redesigned `DogProfileCard` (cover photo on top; below: name, basic-info row
  age·size·gender, distance "N km away", a "See more" affordance; urgent badge overlaid small). A
  filter sheet (gender/size/age/energy/good-with/vaccination) composes; "Clear all" resets. Header
  shows "NEAREST FIRST" vs "RECENTLY ADDED".
- **Fallback:** permission denied or no provider coords → the server returns featured/recent (no
  crash, no empty grid). Empty state: "No dogs near you yet" / "No matches" when filters exclude all.

## Web mirror
The consumer UI in this app is the mobile app (the web app is the provider dashboard — no consumer
discovery page exists). The new `GET /api/adoption/listings` is the platform-agnostic shared layer a
future web consumer view would reuse verbatim.

## Acceptance ✅
Cards show photo-then-info (pet fully visible); nearest-first verified with seeded coords (integration
test); each filter + a tight radius narrow correctly; permission-denied falls back cleanly; empty
state when nothing matches; web + integration + mobile tests green.

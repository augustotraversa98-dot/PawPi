# 2.70 — Transport live-GPS tracking (Wave 7)

Read `00-README.md` (the ⚡ autonomy preamble + shared conventions) first. Web + mobile + migration. This is
the **planned follow-up to 2.52** (which explicitly deferred live GPS) and mirrors the walker-GPS pattern
(2.7). ⛔ **Build after 2.68** (reuses the shared Apple-Maps `MapLocationView`). Extend `transport_trips`;
do NOT rebuild transport, booking, chat, or the map.

```

CONTEXT
- 2.52 built transport_trips on the spine (owner + provider-staff + assigned-driver RLS; statuses
  requested→confirmed→en_route→completed→cancelled). The 2.52 ticket explicitly logged live GPS as the
  follow-up — this is it.
- The walker-GPS pattern (2.7) is the model: the worker (driver) posts {lat,lng,t} points while the trip is
  in_progress; the owner live-polls and watches the track grow. The owner walk-live screen
  (anything/apps/mobile/src/app/walk-live.jsx) live-polls useWalkSessions (5s) — reuse this polling shape.
  NOTE: walk-live drew an SVG polyline because no map was wired; for transport, render the live position +
  route on a REAL Apple map via the 2.68 MapLocationView (markers + polyline). This is the upgrade.
- The driver is an active provider_staff member assigned to the trip (assigned_staff_id). Live pings are
  posted by the driver only while status='en_route'.

GOAL
While a pet-taxi trip is en_route, the assigned driver's app posts location pings; the owner opens a live
map and watches the vehicle move toward dropoff (pickup + dropoff markers + the live driver marker + the
travelled polyline + ETA-ish distance/time readout). When the trip completes, the same screen shows the
final route summary. Real data only — no fake routes, no simulated movement.

SCOPE
- Migration (next free — check supabase/migrations/ at build time; expected 0056):
  transport_trip_locations (id, trip_id FK transport_trips, lat numeric, lng numeric, recorded_at timestamptz
  default now(), posted_by_staff_id FK provider_staff nullable). ENABLE+FORCE RLS, modeled on transport_trips
  + the walk-session location pattern:
    • INSERT only by the trip's assigned driver (active staff, assigned_staff_id = caller) while the trip is
      en_route — via a SECURITY DEFINER helper that reads transport_trips (e.g. app_can_post_trip_location(
      trip_id)) to avoid RLS recursion; pinned search_path, GRANT EXECUTE to pawpi_app.
    • SELECT by the trip OWNER, the assigned driver, and active staff of the trip's provider; everyone else
      zero. Reuse app_is_active_staff_of; add the DEFINER helper(s) the same way 2.52/2.53 did.
  Harness proofs as pawpi_app: assigned driver inserts while en_route (and CANNOT once completed/cancelled);
  owner + provider staff read; other-provider staff + outsiders get zero; a non-assigned staffer can't post.
  Completeness guard green. Flag in docs/test-backlog.md ACTION 1 (Tats hand-applies).
- Web API: a driver POST .../transport-trips/[id]/locations (append a ping; rejects unless caller is the
  assigned driver + trip en_route) and an owner/staff GET .../transport-trips/[id]/track (the trip's pings
  ordered, + the trip's pickup/dropoff). Reuse the existing transport route patterns from 2.52.
- Mobile:
  • Driver side: while a trip is en_route, a "Share live location" affordance posts pings periodically via
    expo-location (foreground; reuse the 2.7 walker posting approach). Degrade gracefully if permission
    denied (clear message, no crash). Stop on complete/cancel.
  • Owner side: a "Track live" entry on an en_route trip → a live screen using 2.68 MapLocationView: pickup
    + dropoff markers, the live driver marker (latest ping), the travelled polyline, distance/elapsed
    readout, LIVE indicator; live-poll like walk-live. On completion show the final route summary. Empty/
    waiting state ("Waiting for the driver's location…") when no pings yet.
- i18n: new strings via t() EN+ES.
- Tests: web vitest (ping POST allowed only for the assigned driver while en_route, rejected otherwise;

  polyline from real pings + the waiting state; driver posts pings only while en_route; map mocked).
```

# 2.3 — Payments foundation (MercadoPago split + Binance Pay) — cross-cutting unlock

Read `00-README.md` + `../phase2-superapp-master-plan.md` §3 first. This is the money layer every
monetized service reuses. Scaffold so Tats only adds accounts/keys.

```
ORIENTATION
PawPi web API (anything/apps/web) + Supabase. Phase-2 ticket 2.3: build the marketplace PAYMENTS
foundation. Model = SPLIT PAYMENTS (owner pays → platform commission + provider payout). Two rails:
MercadoPago (fiat, primary; OAuth-per-provider split payments + Checkout + webhooks — region is LATAM/
sa-east-1) and Binance Pay (crypto; merchant QR/deeplink, settle USDT, Payout API). Read
docs/phase2-tickets/00-README.md + master plan §3, the provider spine (providers/provider_staff),
2.1's provider_capabilities, sql.js, and a recent RLS migration for the pattern.
Branch ticket/payments-foundation off origin/main; squash-merge; migration hand-applied after merge.
Gates: npm test + npm run test:integration (RLS on the money tables is critical).

GOAL: a provider-agnostic payment layer + DB so any service can take a payment and pay out a provider;
both adapters present behind env keys (no real keys committed); provider account-connect flow ready.

SCOPE
- Migration (all RLS'd, strict scoping):
  - provider_payment_accounts (provider_id, rail['mercadopago'|'binance'], oauth/account tokens or
    handle, status) — per-provider connection. SELECT/write: provider admin only; tokens never exposed
    to owners.
  - orders (id, owner_user_id, provider_id, kind['booking'|'product'|'adoption_fee'|'donation'|'subscription'],
    amount_cents, currency, status, ref to the source row e.g. booking/appointment id) + order_items
    (for shop).
  - payments (id, order_id, rail, external_id, status['pending'|'approved'|'refunded'|'failed'],
    amount_cents, commission_cents, raw_status, created_at) — the attempt/result ledger.
  - payouts (id, provider_id, rail, amount_cents, status, external_id) — provider settlements.
  - subscriptions (id, owner_user_id, provider_id, plan, status, next_charge_at) — for shop auto-reorder.
  - RLS: owner sees their orders/payments; provider sees orders/payments/payouts for their provider
    (active staff); payment_accounts = provider admin only; nobody cross-reads. Money = strictest.
    Harness proofs (owner isolation, provider-staff scope, no cross-leak) + completeness guard.
- Payment layer (provider-agnostic module, e.g. src/app/api/utils/payments/): createCheckout(order),
  handleWebhook(rail, payload), getStatus(payment), refund(payment), payout(provider, amount). Behind
  it: a MercadoPago adapter (Split Payments / Checkout, OAuth token per provider, commission %, webhook
  signature verify) and a Binance Pay adapter (create order → QR/deeplink, webhook verify, settle USDT;
  payout via Payout API). Adapters read env keys (MP_CLIENT_ID/SECRET, BINANCE_PAY_KEY/SECRET, platform
  commission %) — if unset, the route returns a clear "payments not configured" error (never crash).
  Idempotency keys; status reconciliation.
- Routes: POST /api/payments/checkout (create an order + checkout for a given kind/ref), webhook
  endpoints /api/payments/webhooks/mercadopago + /binance (signature-verified, update payment/order
  status), GET /api/payments/[id] (owner/provider scoped), POST refund/payout (provider admin/platform).
  Provider OAuth connect: GET start + callback for MercadoPago (store token in provider_payment_accounts);
  Binance handle capture.
- Vitest: the layer + routes with MOCKED adapters (checkout creates order+payment; webhook flips status
  + is signature-checked; refund/payout; owner/provider scoping; "not configured" path). Integration:
  RLS on all money tables.
- .env additions documented + a commented block (NOT committed real values): MP_CLIENT_ID/SECRET,
  MP_WEBHOOK_SECRET, BINANCE_PAY_API_KEY/SECRET, PLATFORM_COMMISSION_BPS, redirect/webhook URLs.

WHAT TATS DOES (document in PR, do NOT block on): create the MercadoPago marketplace app (OAuth
client) + Binance Pay merchant account, set env keys, register redirect/webhook URLs, complete each
provider's OAuth connect. Sandbox first.

DO NOT: commit real keys; hardcode a single rail; let a missing key crash a route; expose provider
tokens to owners; skip RLS/webhook-signature verification. No fake transactions in prod paths.

VERIFY: npm test + integration green (baseline + net-new). PR body: the layer + both adapters
(key-stubbed), the money-table RLS, the OAuth-connect flow, and the exact env/account steps Tats must
do. Migration hand-applied after merge. Confirm origin/main before next.
```

# 2.11 — Shop / e-commerce module (catalog, orders, subscriptions)

Read `00-README.md` + `../phase2-superapp-master-plan.md` (§1 shop row, §3 payments) first. Depends on:
2.1 (capability), 2.3 (payments — required). Capability = `shop`.

```
ORIENTATION
PawPi web API + mobile. Phase-2 ticket 2.11: the SHOP module — a provider sells products (food, toys,
meds) with a catalog, inventory, cart/orders, delivery, and subscriptions/auto-reorder. Read
docs/phase2-tickets/00-README.md + master plan §1/§3. Gate with requireProviderCapability(
providerId,'shop'). Orders + payments REUSE 2.3 (orders/order_items/payments/subscriptions already
exist there — extend, don't duplicate). Reuse Storage for product images.
Branch ticket/shop-ecommerce off origin/main; squash-merge; migration for products/inventory.
Gates: npm test + npm run test:integration.

GOAL: a shop publishes products with stock; owners browse, add to cart, checkout (pay via 2.3),
optionally subscribe (auto-reorder, e.g. monthly food); orders have status/fulfillment.

SCOPE
- shop_products table (RLS'd): provider_id, name, description, image_urls[], price_cents, currency,
  stock_qty, category, is_rx (vet-prescription-required flag), active. Provider-admin writes; published
  shop's active products readable by any authed (discovery). 
- Cart → order: reuse 2.3 orders (kind='product') + order_items (product_id, qty, unit_price). Checkout
  via the 2.3 payment layer (split → provider payout). Decrement stock on paid; restock on refund.
  Fulfillment status (placed/paid/shipped/delivered/cancelled).
- Subscriptions/auto-reorder: reuse 2.3 subscriptions (plan = a product + cadence) → recurring orders +
  charges; owner manage/cancel.
- Rx products: if is_rx, require a valid vet relationship/prescription (consent or a vet note) before
  purchase — mirror the consent model; document the check.
- mobile: owner — browse shop, cart, checkout, manage subscriptions, order history; shop (web
  dashboard) — product/inventory management + orders. Discovery ?type=shop under Services → Shop.
- Tests: capability gate; product CRUD; cart→order→pay (mocked 2.3) → stock decrement; subscription
  recurring; Rx gate; RLS on products/orders.

DO NOT: duplicate the 2.3 order/payment tables; sell out-of-stock; bypass the Rx check; bypass
capability gate. No fake products.

VERIFY: npm test + integration green. PR body: catalog/inventory, order↔2.3 reuse, subscriptions, Rx
gate, RLS. Migration hand-applied after merge. Confirm origin/main.
```

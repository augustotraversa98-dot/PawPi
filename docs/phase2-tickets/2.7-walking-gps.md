# 2.7 — Dog walking module (GPS tracking)

Read `00-README.md` + `../phase2-superapp-master-plan.md` (§1 walking row) first. Depends on: 2.1, 2.4,
2.3, 2.5 (chat for live coordination). Capability = `walker`.

```
ORIENTATION
PawPi web API + mobile. Phase-2 ticket 2.7: the WALKER module — scheduled + on-demand walks with LIVE
GPS tracking, check-in/out, and a walk report that flows into the pet's health logs. Read
docs/phase2-tickets/00-README.md + master plan. Gate routes with requireProviderCapability(
providerId,'walker'). Reuse generalized booking (2.4; supports on-demand + recurring/pack walks),
payments (2.3), chat (2.5), and the existing health-log/walk-log write path (health_walk_logs) +
pet timeline. The mobile app already has walk-activity/route concepts — read them and reuse, don't
duplicate.
Branch ticket/service-walking off origin/main; squash-merge; migration for the walk-session/GPS table.
Gates: npm test + npm run test:integration.

GOAL: owner books a walk (scheduled or on-demand) → walker checks in, the route is GPS-tracked live →
owner watches → walker finishes → a walk report (distance/duration/route/potty/notes/photos) is saved
and surfaced to the owner + the pet's health timeline.

SCOPE
- Booking: capability=walker via 2.4 (on-demand = immediate slot; recurring = pack/weekly). Fee via 2.3.
- walk_sessions table (RLS'd): booking_id, pet_id, owner_user_id, provider_id, staff_user_id, status
  (scheduled/in_progress/finished/cancelled), started_at, ended_at, distance_m, duration_s, route
  (jsonb array of {lat,lng,t} or a path), potty (pee/poo flags), notes, photo_urls[]. Provider/walker
  posts GPS points during the walk; owner reads live.
  RLS: owner sees their walk sessions; active walker-staff of the provider can write the session they're
  assigned; participant-scoped. Harness proofs.
- Live tracking: walker app posts location updates (throttled); owner subscribes (Supabase Realtime or
  short polling — document). Don't over-build.
- Walk report on finish → write a health_walk_log (distance/duration/route summary) into the pet's
  health timeline (reuse the existing path + the right consent/scope; mirror current permissions).
- mobile: owner — book + live map + report; walker — start/track/finish (reuse existing walk-activity
  UI). Discovery ?type=walker under Services → Dog Walking.
- Tests: capability gate; session lifecycle; GPS points scoped to participants; report → health log;
  RLS.

DO NOT: bypass capability gate; expose live location to non-participants; write health data without the
right scope; rebuild booking. No fake routes/data.

VERIFY: npm test + integration green. PR body: GPS session model, live-tracking choice, report→health,
RLS. Migration hand-applied after merge. Confirm origin/main.
```

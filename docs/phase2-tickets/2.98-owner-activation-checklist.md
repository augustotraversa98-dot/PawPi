## Context
New pet owners do a basic setup at onboarding (name / breed / photo — `apps/mobile/src/app/onboarding.jsx`)
but nothing then drives the high-value first actions or a daily-return habit. The building blocks ALL
already exist and this ticket only surfaces + nudges them:
- Posts / daily moments (the feed) — for "share your first post".
- Health **Reminders** (`apps/mobile/src/components/Health/Reminders/`, local-notification scheduling via
  `expo-notifications` + the `headsUpReminders` / `notifications.leadTime` utils) — meals/walks/vaccinations/
  medicines reminders already exist.
- Health/food logging (`0008_health_logs`, the nutrition screen) — for "log your first meal".
- The pet medical/history profile (`(tabs)/more/profile-edit.jsx`) — for "complete your dog's history".
- Notification permission (`expo-notifications`) + the in-app notifications screen.
There is NO checklist/activation/progress concept in the app yet — this is net-new UI over existing data.

## Current issue
Nothing drives first-week activation or gives the owner a reason to come back daily.

## Expected behavior
1. **Persistent "Getting started" card at the top of the Home tab**, showing a progress ring/bar with a
   **% complete**. It stays visible until **100%**, then plays a brief celebration (confetti / paw) and
   retires. No manual dismiss — it's derived, so it disappears only when everything's done.
2. **Checklist items** — each COMPLETION is DERIVED from real data (never a stored flag), each row taps
   through to the existing screen that completes it, and each shows done/undone with a satisfying check:
   - **Add your dog's basics** (name + breed) — from onboarding; usually already done → shows checked as an
     immediate early win.
   - **Complete your dog's history** — key medical/history profile fields filled (define a small, sensible
     "complete" set; tap → profile-edit).
   - **Set your first reminder** — meals / walks / vaccinations / medicines → the existing Reminders flow
     (≥1 reminder exists).
   - **Log your first meal** — ≥1 food/health log (tap → the logging/nutrition flow).
   - **Share your first post** — ≥1 post (tap → the composer).
   - **Turn on notifications** — OS notification permission granted.
   `%` = completed ÷ total. Real derivation only (posts count, reminders count, health-log count, profile
   completeness, permission status).
3. **Engaging:** progress ring, encouraging copy, a clear per-item CTA, check animations, and a genuine
   celebratory moment at 100%. This is the new user's first impression — make it feel good, on-brand
   (coral/cream), not a dull todo list.
4. **Daily-return habit:** when the user turns on notifications, schedule a **recurring daily local
   reminder** (reuse the existing `expo-notifications` scheduling utils — once per day, mid-morning, e.g.
   "Time to check on {PetName} 🐾"). Schedule exactly once (never double-schedule; cancel+reschedule
   cleanly), and only when permission is granted (no nagging if denied).
5. EN + ES, neutral "tú".

## Data / API rules
No migration. Completion derives from existing endpoints/state (posts, reminders, health logs, pet profile
fields, notification permission). If one aggregate read is cleaner than several client checks, add a GET
that COMPUTES activation status from existing tables (no new table) and test it through the real router;
otherwise reuse the existing reads. Reuse every target screen — this ticket adds the checklist surface + the
daily reminder scheduling, nothing else.

## Acceptance criteria
- `npm test` (mobile jest) green + baseline, plus tests: each item's completed/not-completed derivation; the
  `%` math; the card hides at 100%; the notification-permission item reflects real permission; the daily
  reminder is scheduled once on enable and not duplicated on re-render.
- DEVICE PASS: a fresh-ish account shows the checklist with correct progress; completing an item ticks it and
  bumps the %; enabling notifications schedules the daily reminder; at 100% it celebrates and disappears.
- Update `docs/roadmap.md` + `PawPi_instructions.md` status block + `docs/night-run-log.md`; add the Wave 11
  index entry to `00-README.md`.

## Context
`provider_posts` (0042) supports comments (0082) + moderation (0066) but has **no like/paw primitive** —
there is no `provider_post_paws` table and no like endpoint. Ticket 2.93 builds the business social header
with a **Paws** stat slot that currently reads 0; this ticket makes paws real. The pet feed already has a
"paw" like with a double-tap gesture (ticket 2.64) — mirror that interaction + visual for consistency.

## Current issue
A pet owner can't paw/like a business post, and the Paws stat on the business profile (2.93) has no real
data behind it.

## Expected behavior
1. A signed-in pet owner can **paw (like)** a business post — via a tap on a paw control AND a double-tap on
   the image (mirror the 2.64 pet-feed gesture + brand-color paw animation). Optimistic, persisted, toggles
   off on a second paw. A guest is prompted to sign in.
2. The post shows its **paw count**; the business profile stat row (2.93) shows **total Paws** across the
   provider's posts as real data.
3. Reuse the pet-feed paw components/animation where practical; do not fork a new like system.

## Data / API rules
- **Migration** (next free number): `provider_post_paws` (`post_id` → `provider_posts(id)` ON DELETE
  CASCADE, `user_id` → user, `created_at`, `unique(post_id, user_id)`). **ENABLE + FORCE RLS** mirroring the
  newest provider-owned tables: a user manages ONLY their own paw rows (`user_id = current_app_user_id()`
  for insert/delete); counts readable by any authed caller (edge table, no private data). Add as-`pawpi_app`
  harness proofs + completeness-guard classification.
- **Degrade cleanly pre-apply:** every `provider_post_paws` query must catch the undefined-table error
  (`42P01`) and return 0 / not-pawed; the paw action no-ops until the table exists. Never 500, never crash
  the post or profile.
- API (all tested through the REAL Hono router by URL; verify no static-vs-`[param]` shadowing on the new
  paw sub-route): paw, unpaw, is-pawed + paw count on the post; total-paws on the provider profile payload
  consumed by 2.93.

## Acceptance criteria

  proves the RLS: a user creates/deletes only their own paw; cross-user writes denied; counts read cleanly.
- URL-level tests: paw → is-pawed true + count +1; unpaw → false + −1; guest denied; missing-table path
  returns the degraded 0 without a 500.
- Mobile jest: tap + double-tap paw toggles optimistically, calls the endpoint, reverts on error; guest →

growth/virality feature: after posting the daily, let the user share a cute branded image.

```
ORIENTATION
PawPi Expo mobile. Phase-2 ticket 2.28: a shareable, nicely-FRAMED version of the daily photo for
Instagram Stories + X. Read docs/phase2-tickets/00-README.md.
Branch ticket/daily-share-frame off origin/main; squash-merge. NO migration. Gate: npm test (mobile jest).
Confirm the mobile baseline first.

CONTEXT (read before editing)
- apps/mobile/src/components/Feed/PostComposerModal.jsx — the daily composer (onPost({ photo, caption })).
  The share entry point lives AFTER a successful daily post (a "Share" CTA on the success state) and/or
  on the user's own post card (components/Feed/PostCard.jsx / DailyPromptCard.jsx).
- The pet name + photo are available from the post / current pet (useCurrentPet via usePetProfile).
- The BeReal daily-lock must stay EXACTLY as-is — this only adds a share affordance on an already-posted

  share sheet). Confirm what's already installed; add the minimal set. Check Expo Go vs dev-build support
  and note it.

GOAL: tapping "Share" on the user's daily produces a story-sized branded image — the dog's photo in a
cute PawPi frame reading "[Dog name] is part of PawPi" — and opens the share sheet (Instagram Stories, X,
etc.). For X, also offer a nice pre-filled caption. Tasteful, on-brand (the warm PawPi palette).

SCOPE
1. A ShareableDailyCard component: an off-screen/preview styled view sized for stories (1080×1920 ratio,
   9:16) — the photo, a soft PawPi-branded frame (logo + warm palette, rounded, a little paw motif), and
   "[Dog name] is part of PawPi 🐾". Keep it cute + minimal; match COLORS. (Exact art is a judgment call —
   make it tasteful; Tats will eyeball + tweak on device.)
2. Capture it to an image with react-native-view-shot (captureRef → a temp file/URI).
3. Share via expo-sharing / the native share sheet. Provide an enhanced default TEXT for X (e.g.
   "Meet [Dog name] 🐾 today's daily on PawPi — [a cute line]"). Instagram Stories receives the image;
   if a direct IG-Stories deep link is easy, offer it, else the generic share sheet is fine.
4. Entry points: a "Share" button on the post-success state and on the user's own daily post card. Handle
   permissions + a graceful fallback if sharing/capture is unavailable (no crash).
5. Tests: mobile jest — the share handler captures the card + invokes the share API with the image + the
   enhanced text (mock view-shot + sharing); the frame renders the real pet name; the BeReal lock /
   posting flow is untouched.

DO NOT: change the daily-post flow, the BeReal lock, or the feed; add a backend/migration; block on a
heavy design system; ship a frame that hides the photo. Keep it optional (sharing is never forced).

VERIFY: npm test (mobile) green (baseline + net-new). PR body: the ShareableDailyCard + capture + share,
the X caption, entry points, deps added (+ Expo Go/dev-build note), lock untouched. DEVICE PASS
(docs/test-backlog.md): post the daily → Share → the framed image looks cute → shows in the IG-Stories /
X share sheet → posts; eyeball the frame design.
```

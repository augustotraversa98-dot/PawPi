# 2.85 — Adoption listings: image + video upload (Wave 9)

**Status:** BUILT — CI-green. No migration (columns exist since 0038).

## Goal
Wire real media upload into the provider's adoption listing editor: multiple photos
(→ `photo_urls[]`) and a short intro video (→ `video_url`). First photo = cover; reorder/remove.

## What shipped (`provider/components/ProviderAdoption.jsx`)
- **Create form:** reuses the shared `ImageUploader` (2.23) for photos (ordered array → `photo_urls[]`,
  first is the cover, add/remove/reorder) + a new `VideoUploader` for one video (→ `video_url`). Both
  go through the existing Supabase Storage upload path (`useUpload`). The create POST now sends
  `photo_urls` + `video_url`.
- **Listing list:** shows the cover photo (`photo_urls[0]`) as the thumbnail (falls back to the dog
  icon when none) + a "N photos · video" summary, and a new **Media** button that opens a
  `ListingMediaModal` to edit photos (reorder/remove) + video on an existing listing, saved via the
  existing `useUpdateAdoptableListing` PATCH.

## Data
Reuses `adoptable_listings.photo_urls text[]` + `video_url text` (migration 0038). **No migration.**
Owner/provider-scoped writes via the existing adoptable-listings CRUD (0038 RLS + the `adoption`
capability gate). No fake/sample images — empty state shows the dog-icon placeholder.

## Acceptance ✅
A listing saves with real uploaded photos + video; cover = first photo; remove/reorder persists
(through the create form and the per-listing Media editor); empty state when none; provider-scope RLS
holds (existing 0038 policy); web tests green.

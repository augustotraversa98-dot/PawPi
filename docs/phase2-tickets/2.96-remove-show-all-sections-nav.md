## Context
The provider dashboard left nav (`apps/web/src/app/provider/components/ProviderShell.jsx`, `Sidebar`) is
capability-gated via `navItemVisible(item, capabilities, showAll)` + `NAV_REQUIRES`: a capability-gated
section (shop→Products, vet→Clinical, daycare, trainer→Training, adoption, pharmacy→Rx Fulfillment,
insurance→Policies) only shows when the provider holds that capability; structural sections (Dashboard,
Chats, Storefront, Profile, Staff, Sales) always show. BUT there is a **"Show all sections" escape hatch**:
a `showAll` state (~line 330) + a button (~lines 384–395) that, when clicked, reveals EVERY section
regardless of what the business selected.

## Current issue (reported on device)
Northside does NOT have "Rx Fulfillment" selected, yet clicking **"Show all sections"** makes it (and every
other unselected section) appear. The left panel should show ONLY the sections selected under "what this
business offers" — selected → shown; not selected → not shown, with no override.

## Expected behavior
1. **Remove the "Show all sections" escape hatch entirely** — delete the `showAll` state, the toggle button
   block, and the `showAll` parameter/branch in `navItemVisible`. A capability-gated section appears in the
   left nav ONLY when the provider holds its capability (driven by the offerings selected on the Business
   Profile, which already updates the nav reactively). There is no way to reveal an unselected offering
   section from the nav.
2. Structural, non-offering sections (Dashboard, Chats, Storefront, Profile, Staff, Sales — the keys not in
   `NAV_REQUIRES`) still always show — those are not "offerings" and must not disappear.
3. Keep the existing safety that the currently-active section is never hidden (a deep link into a module's
   route still highlights its row) — that behavior is independent of the removed escape hatch.
4. The per-module server capability guards and each route's own "this business doesn't offer X" page are
   unchanged — this ticket only changes what the SIDEBAR lists.

## Data / API rules
No migration, no API change — provider dashboard nav only. Reads the already-available
`provider_capabilities` the profile writes.

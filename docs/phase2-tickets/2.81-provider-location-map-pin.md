# 2.81 — Provider onboarding: map pin for the business location (Wave 9)

**Status:** BUILT — CI-green. No migration. New env key flagged for Tats.

## Problem
Mobile business onboarding and the web provider profile captured the business location as free text,
so addresses were imprecise — and nearest-first adoption (2.86) needs accurate provider lat/lng.

## What shipped
Reuses the existing shared map components (ticket 2.68) — **no new map was built**.

- **Mobile (`app/vet-business-access.jsx`):** the onboarding form now shows the shared `LocationField`
  (map pin + address line; address and lat/lng stay in sync). After the provider is created, the pin
  persists as the provider's **primary `provider_locations` row** via the new
  `useCreateProviderLocation` hook → `POST /api/providers/[id]/locations`. Best-effort: a failed
  location write never blocks the created-business success state.
- **Web (`provider/components/ProviderLocations.jsx`):** the add/edit location form now shows an
  interactive Google-map pin (`LocationMapPicker`, wrapping the existing
  `@vis.gl/react-google-maps` integration). Click or drag → the lat/lng inputs update; the inputs and
  pin stay in sync. The manual lat/lng inputs remain (readout + manual entry).

## Data
`provider_locations.lat`/`lng` (`numeric(9,6)`) already exist (migration 0014) and the location
route already accepts + validates them — **no migration, no schema change**. lat/lng round to 6dp.

## Degrade-clean
- **Mobile:** location is optional. A typed address still saves when location permission is denied
  (only "My location" needs GPS; tap-to-drop + the address line work without it).
- **Web:** the interactive map is gated behind `NEXT_PUBLIC_GOOGLE_MAPS_BROWSER_KEY`. When unset
  (incl. all CI/jsdom), `LocationMapPicker` renders nothing and the form falls back to the manual
  lat/lng inputs — no crash, no key shipped. **FLAG for Tats:** set this browser Maps JS API key to
  enable the web pin (the mobile pin uses Apple Maps via `PROVIDER_DEFAULT`, no key needed).

## Tests
- Mobile `vet-business-access.test.jsx`: pin → primary-location POST with the right body; no
  pin/address → no POST; failed location write still shows success (degrade).
- Web `LocationMapPicker.test.jsx`: not-configured + renders-null degrade path. Existing
  `ProviderLocations.test.jsx` (incl. lat range validation) stays green.

## Acceptance ✅
Pin + address stay in sync; saved lat/lng persist on the primary location row; degrades clean when
location permission is denied (manual address still saves); mobile + web tests green.

# 2.19 — Fix More-tab navigation corruption (mobile)

Read `00-README.md` first. **Mobile-only, frontend-only, NO migration.** Independent — no blocker, can be
built anytime; recommended FIRST in Wave 4 because it's a broken core navigation flow. This is the
long-standing "More-tab navigation corruption" bug in `PawPi_instructions.md`.

```
ORIENTATION
PawPi Expo mobile app (expo-router). Phase-2 ticket 2.19: fix the More-tab navigation corruption. Read
docs/phase2-tickets/00-README.md.
Branch ticket/nav-more-tab-fix off origin/main; squash-merge. NO migration. Gate: npm test (mobile jest).
Confirm the mobile baseline first.

THE BUG (reproduce first)
- Open the Services tab → Veterinary (or any service) → tap "back": it returns to the WRONG section, and
  the More tab is now corrupted — tapping More shows the vet/service screen nested INSIDE it, and the only
  way to recover the real More landing page is to kill and reopen the app.

ROOT CAUSE (confirmed in the repo — verify, then fix at the root)
- apps/mobile/src/app/(tabs)/_layout.jsx — the bottom tabs are Feed(index) / Health / Training /
  Services(services.jsx) / More(more/index).
- apps/mobile/src/app/(tabs)/more/_layout.jsx — the More tab is a Stack that OWNS the shared service
  screens: vet, grooming, walking, sitting, shop, adoption, provider, plus community/hub/data-access/
  profile/settings.
- So when the SERVICES tab navigates to a service detail (e.g. router.push to a more/* route), it PUSHES
  that screen onto the MORE tab's stack. After that, More's stack root is buried under the service screen
  → tapping More shows the service, and "back" resolves against the wrong stack. That cross-tab push into
  the More stack is the corruption.

EXPECTED BEHAVIOR (from PawPi_instructions.md "Navigation principles")
- The More bottom tab ALWAYS opens the More landing page (its stack root), never a stale nested screen.
- Visiting a service from the Services tab returns to the Services tab on "back" — it must NOT mutate the
  More tab's stack.
- Switching bottom tabs resets/closes any in-progress modal or pushed flow so a tab root is never corrupted.
- Back returns to the correct parent depending on where the screen was opened from.

SCOPE (do the ROOT fix; the tabPress reset is a belt-and-suspenders safety net, keep both)
1. ROOT: stop Services-tab navigation from pushing onto the More stack. Give the shared service screens a
   home that the Services tab owns (e.g. a services/ stack under the Services tab, or a shared route group
   outside the More stack), and route BOTH entry points (the Services grid AND any More entry, if one
   remains) to that home — so opening a service never lands inside more/. Keep deep links working. If a
   service screen must remain reachable from More, it should open in a way that doesn't bury More's root
   (e.g. its own stack), not by pushing into more/_layout's stack.
2. SAFETY NET: add tabPress listeners in (tabs)/_layout.jsx so tapping a bottom tab resets that tab's
   stack to its root (popToTop / navigate to the tab's index) and dismisses any open modal — so even an
   unforeseen push can't leave the More tab stuck. (expo-router: Tabs.Screen `listeners={{ tabPress }}`
   or the equivalent; reset to the tab's root route.)
3. Confirm routine-creation modals (the other half of the documented bug — "More opens inside a stale
   routine creation flow") also close/reset on bottom-tab switch.
4. Tests (jest): a service opened from the Services tab does NOT appear in the More stack and "back"
   returns to Services; tapping the More tab resolves to more/index even after a service was visited; a
   tab switch dismisses an open modal. Pure navigation-state assertions where possible (mock the router /
   assert reset is called) — keep it deterministic.

DO NOT: add a migration; mask the bug with only the tabPress reset while leaving the cross-tab push in
place (fix the root); change unrelated screens; break existing deep links into service screens.

VERIFY: npm test (mobile) green = baseline + net-new. PR body: the root cause (service screens in the
More stack reached from Services), the structural fix, the tabPress safety net, and the modal-reset.
DEVICE PASS (docs/test-backlog.md): Services → Veterinary → back returns to Services; More always opens
its landing page; no app-restart needed; repeat for each service + the routine-creation flow.
```

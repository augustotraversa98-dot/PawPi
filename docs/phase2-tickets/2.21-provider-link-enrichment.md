# 2.21 — AI-assisted business enrichment from links (confirm-first import)

Read `00-README.md` + `../phase2-superapp-master-plan.md` first. Depends on: 2.20 (the links are the
input). ⛔ **DO NOT START until 2.20 is merged to `origin/main`.** **Web-first, backend-led.** No new
table required (writes existing provider/location/service draft fields). **Product decision locked
(Tats): CONFIRM-FIRST import — never auto-publish unverified data.**

```
ORIENTATION
PawPi web API. Phase-2 ticket 2.21: enrich a provider's profile by reading their links and PROPOSING a
draft the provider reviews before publish. Read docs/phase2-tickets/00-README.md.
⛔ PREREQUISITE: 2.20 must be merged (the website/IG/FB/Maps link columns). Confirm origin/main has it.
Branch ticket/provider-link-enrichment off origin/main; squash-merge.
Gate: npm test (web vitest) + (if any DB write path changes) npm run test:integration. NO migration unless
you add an optional import-status column (see SCOPE) — prefer none. Confirm baselines first.

GOAL: on the provider dashboard, a provider taps "Import from the web" → the backend fetches their
website + Google Maps Place and returns a PROPOSED draft (business hours, address, phone, a short
description, candidate services/prices, candidate photos). The provider REVIEWS and EDITS it, then
chooses what to apply. NOTHING is published or saved live until the provider confirms (no-fake-data rule:
unverified data never goes live). Onboarding stays fast: paste links (2.20) → review draft → done.

SCOPE
- New backend enrichment seam apps/web/src/app/api/utils/enrichment/ (provider-agnostic, dormant-safe):
  * fetchWebsiteSummary(url) — fetch the website HTML, extract readable text, and (optionally) run it
    through an LLM to STRUCTURE messy text into { description, services:[{name,price?,duration?}] }.
    LLM call behind an env key (e.g. ENRICHMENT_LLM_KEY); MISSING key → skip the LLM step gracefully and
    return only what plain parsing found (mirror the payments "not configured → clean, no crash" pattern).
  * fetchGooglePlace(mapsUrlOrQuery) — Google Places Details (hours, formatted address, phone, lat/lng,
    a few photo refs) behind GOOGLE_PLACES_API_KEY; missing key → skip cleanly.
  * IG/FB: DO NOT scrape (auth-walled / ToS). Just carry the stored links through (2.20). At most, link
    out / embed.
- Route POST /api/providers/[id]/enrich (requireProviderRole owner|admin) → returns a PROPOSED draft
  object ONLY (does NOT write providers/locations/services). Clean 503-style "enrichment not configured"
  when no keys. Best-effort per source: one failing source doesn't fail the whole call (return what we got
  + per-source status).
- Apply step = the provider's EXISTING save routes (profile PATCH 2.20, locations/services CRUD). The UI
  pre-fills the edit forms from the draft; the provider edits + saves through those existing endpoints.
  Do NOT add a privileged auto-write path. (If you want a one-shot "apply all", it must still go through
  the owner-identity routes so RLS + validation apply.)
- Photos: candidate image URLs are PROPOSED; applying one routes through the existing Supabase Storage
  upload/logo path — the provider picks; nothing auto-attaches.
- Web dashboard: an "Import from the web" button on the profile/onboarding screen → loading → a review
  panel (each field with the proposed value + an apply/skip toggle) → save via the existing routes.
- (Optional, only if you want progress UX) a providers.enrichment_status text column (migration) — PREFER
  to skip; the draft is ephemeral. If you add it, it's additive + rides providers' existing RLS.
- Tests: vitest — /enrich returns a draft from mocked website+places responses; missing keys → clean
  "not configured" (no crash, no throw to the client); a failing source is isolated; the route NEVER
  writes provider data directly (assert no INSERT/UPDATE on providers/services in the enrich path).

DO NOT: auto-publish or silently overwrite live fields; scrape IG/FB; bypass the owner-identity save
routes when applying; let a missing API key crash; invent data when a source returns nothing (empty →
empty draft, the provider fills it in). No fake data.

VERIFY: npm test (web) green (baseline + net-new). PR body: confirm-first model (propose → review →
apply-via-existing-routes), the website+Places seams behind env keys with clean degradation, IG/FB
links-only, no direct provider writes from /enrich. ⚙️ FLAG FOR TATS: set GOOGLE_PLACES_API_KEY +
ENRICHMENT_LLM_KEY when ready (until then "Import" shows a clean "not set up yet"). No on-device check
(web dashboard; verify in browser).
```

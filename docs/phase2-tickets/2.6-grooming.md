# 2.6 — Grooming module

Read `00-README.md` + `../phase2-superapp-master-plan.md` (§1 grooming row) first. Depends on: 2.1
(capabilities), 2.4 (booking), 2.3 (payments), optional 2.5 (chat).

```
ORIENTATION
PawPi web API + mobile. Phase-2 ticket 2.6: the GROOMER capability module. Read
docs/phase2-tickets/00-README.md + master plan. The capability is `groomer` (gate every groomer route
with requireProviderCapability(providerId,'groomer') from 2.1). Reuse the provider spine (services as
the groom menu), generalized booking (2.4), payments (2.3), Storage uploads, and the pet
health/profile timeline. Read the pet-profile + health-logs write paths to route grooming media/notes
into them.
Branch ticket/service-grooming off origin/main; squash-merge; migration only if new tables needed.
Gates: npm test + (if DB) npm run test:integration.

GOAL: a groomer publishes a service menu, owners book a groom, the groomer logs the session with
before/after photos (→ pet profile) and coat/skin notes (→ health logs), with recurring cycles.

SCOPE
- Service menu: groomers use provider_services tagged capability='groomer' (bath, full groom, nail
  trim, spa…) with duration + price. Booking via 2.4 (capability=groomer). Deposit/fee via 2.3.
- Groom session record (new table or reuse the booking + an attachments/notes table, RLS'd):
  groom_sessions (booking_id, pet_id, owner_user_id, provider_id, before_urls[], after_urls[],
  coat_skin_notes, products_used, next_due_at). before/after photos surface on the PET PROFILE; coat/
  skin notes flow into the pet's health timeline (reuse the existing health-log/timeline write).
  Provider writes require active groomer staff + (for pet-data writes) the appropriate consent scope
  (health_logs_write) OR keep grooming media owner-shared by the booking relationship — mirror what the
  routes already permit; document. RLS + harness proofs for any new table.
- Recurring cycles: reuse 2.4 recurrence (e.g., every 6 weeks) → reminders via the existing engine.
- mobile: groomer appears under Services → Grooming (discovery ?type=groomer), book flow, and the
  owner sees before/after on the pet profile + coat notes in health. Empty states, no fake data.
- Tests: capability gate (non-groomer provider → 403); booking+session+media write; recurrence;
  RLS on new tables.

DO NOT: bypass the capability gate; write pet health data without the right consent/scope; duplicate
booking/onboarding (reuse 2.4/spine). No fake data.

VERIFY: npm test + integration green (baseline + net-new). PR body: capability gate, session/media →
profile+health, recurrence, RLS. Migration (if any) hand-applied after merge. Confirm origin/main.
```

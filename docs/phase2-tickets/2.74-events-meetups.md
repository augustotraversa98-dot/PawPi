# 2.74 — Events / meetups (Wave 7)

Read `00-README.md` (the ⚡ autonomy preamble + shared conventions) first. Mobile + web API + migration. A
community feature: owners create + discover local pet events/meetups, set a location on the shared **Apple
map** (2.68), and RSVP. ⛔ **Build after 2.68** (location picker). Sits alongside the community forum (2.44)
+ social walks (2.43); reuse those patterns, don't rebuild navigation/discovery.

```

CONTEXT
- This is a community/social feature, NOT a provider service — model it on the forum (2.44:
  forum_threads/comments/votes, any-authed read, author-only write/soft-delete) + social walks (2.43:
  lat/lng/location_name + the WalkMapPicker, now 2.68). An event has a location → use the 2.68
  MapLocationPicker to set it and MapLocationView to show it.
- The community surface already exists (the 2.39/2.44 Community area). Add Events as a section there; route
  through the existing community/ navigation so no nav corruption (2.19/2.39 hold).
- Notifications (2.44/2.48 used app_notify) can announce an RSVP'd event reminder — best-effort, never
  blocking.

GOAL
An owner browses upcoming pet events/meetups (puppy socials, adoption days, park meetups) near them on an
Apple map + a list, opens an event (title, description, host, date/time, location on the map, attendee
count), and RSVPs (going / not going). An owner can also create an event (title, description, date/time,
location via the 2.68 map picker, optional cover photo, capacity). Hosts edit/cancel their own events.
Real data + empty states; no fake events.

SCOPE
- Migration (next free — check supabase/migrations/ at build time; expected 0060):
  events (id, host_user_id FK user_profiles, title, description text, starts_at timestamptz, ends_at
  timestamptz nullable, lat numeric nullable, lng numeric nullable, location_name text, address text,
  cover_image_url text nullable, capacity int nullable, status text ['published','cancelled'] default
  'published', created_at, updated_at, deleted_at).
  event_rsvps (id, event_id FK events, user_profile_id FK user_profiles, pet_id FK pets nullable, status
  text ['going','not_going'] default 'going', created_at, updated_at, UNIQUE(event_id, user_profile_id)).
  ENABLE+FORCE RLS:
    • events: any-authed READ of a published, non-deleted event (public listing — like forum threads);
      INSERT by the caller as host; UPDATE/DELETE (soft) HOST-ONLY (host_user_id = caller). Model on
      forum_threads author-only write.
    • event_rsvps: a user reads RSVPs for an event they can see (count) + reads/writes their OWN rsvp (the
      caller = user_profile_id); UNIQUE keeps one rsvp per user/event (upsert toggles going/not_going). Use
      a SECURITY DEFINER helper only if a predicate must read events to gate (mind recursion); pinned
      search_path + EXECUTE to pawpi_app. attendee count = COUNT on read, not denormalized (forum pattern).
  Harness proofs as pawpi_app: any-authed reads a published event; non-host can't edit/delete; host edits/
  cancels own; a user manages only their own rsvp; can't rsvp on a cancelled/deleted event; cross-user rsvp
  write blocked. Completeness guard green. Flag in test-backlog ACTION 1.
- Web API: events CRUD (host-scoped writes; published public read) + rsvp upsert + an attendee count. Reuse
  the forum route patterns + sql.js.
- Mobile: an Events section in Community → upcoming list + a 2.68 Apple map of nearby events (markers) →
  event detail (2.68 MapLocationView pin, date/time, host, attendee count, RSVP toggle, "Directions" →
  Apple Maps) → create-event form (title, description, date/time via the existing DateField/TimeField,
  location via 2.68 MapLocationPicker, optional cover via the Storage upload path, capacity) → host
  edit/cancel. Empty states ("No upcoming events near you"). No fake events.
- Notifications: best-effort reminder/announcement via the existing app_notify (e.g. on RSVP) — never block
  on a notify failure; widen the notifications type CHECK additively if a new type is needed (drop+re-add
  like 0050/0051 did for 'lost_alert'/'emergency_contact').
- i18n: new strings via t() EN+ES.
- Tests: web vitest (event CRUD host-scoped + published public read; rsvp upsert own-only + toggle;
  attendee count; can't write others' rsvp; cancelled event hidden/uneditable). integration (events +
  event_rsvps RLS proven as pawpi_app per above; any notifications CHECK widen; completeness guard green).
  mobile jest (list + map render from real events + empty state; create-event posts the right body incl. the
  map location; RSVP toggle; host-only edit affordance).

DO NOT: model events as providers/bookings (this is community, like the forum); rebuild community nav/
discovery or the map (reuse 2.44 + 2.68); let a non-host edit/cancel an event or write another user's rsvp;
denormalize counts; show fake events; gate on provider_type. Migrations hand-applied by Tats — flag in
test-backlog ACTION 1.

VERIFY: npm test + integration green; completeness guard green. PR body: events + event_rsvps with RLS
```

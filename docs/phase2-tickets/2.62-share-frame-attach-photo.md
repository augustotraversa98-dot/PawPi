- The share flow: DailyShareButton (components/Feed/DailyShareButton.jsx) mounts an off-screen
  ShareableDailyCard (components/Feed/ShareableDailyCard.jsx) and snapshots it via react-native-view-shot
  `captureRef`, then opens the system share sheet (2.28). ShareableMemoryCard / MemoryShareButton mirror

GOAL
The shared frame contains the pet's actual daily-moment photo. Capture only AFTER the image has fully
loaded (and the card has laid out); if the photo genuinely can't load, fail gracefully (no blank share —
either skip with a friendly notice or share without crashing), never a blank-center card masquerading as a
photo. Works from every place the share button appears.

SCOPE
- Gate the capture on image load: in ShareableDailyCard, expose the expo-image onLoad/onLoadEnd (and
  onError) so DailyShareButton waits for the image to be ready before calling captureRef (e.g. a ready

  same gating to ShareableMemoryCard / MemoryShareButton.
- Verify the correct photoUri is threaded from every caller (feed PostCard, PostDetailModal, profile grid,
  memories) — the daily-moment image URL, not a missing field. Fix any caller passing nothing.
- Make the off-screen card large enough / properly laid out for a crisp capture (it already renders 9:16);
  ensure the image has finished decoding (expo-image cachePolicy/priority as needed).
- Graceful failure: if onError fires or the timeout hits, do NOT share a blank card — show the existing
  "couldn't share" path (no crash). Keep the no-op when sharing is unavailable (Expo Go).
- Tests: mobile jest (capture is deferred until the image reports loaded; the card receives the real
  photoUri; capture is NOT triggered while photoUri is missing/loading; onError → graceful, no blank
  share; the enhanced caption/text still passed to Sharing.shareAsync).

DO NOT: capture before the image loads; share a blank/placeholder-center card as if it were the photo;
break the 2.28 daily-lock / posting flow; remove the graceful no-op where native sharing is unavailable;

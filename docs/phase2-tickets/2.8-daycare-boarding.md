# 2.8 — Daycare & boarding module

Read `00-README.md` + `../phase2-superapp-master-plan.md` (§1 daycare row) first. Depends on: 2.1, 2.4,
2.3, 2.5. Capability = `daycare`.

```
ORIENTATION
PawPi web API + mobile. Phase-2 ticket 2.8: the DAYCARE/BOARDING module — capacity-managed stays with
check-in/out, daily report cards, owner feeding/med instructions, and VACCINE-REQUIREMENT VERIFICATION
that reads pet_vaccinations. Read docs/phase2-tickets/00-README.md + master plan. Gate with
requireProviderCapability(providerId,'daycare'). Reuse booking (2.4, recurring/multi-day stays),
payments (2.3), chat (2.5), Storage, and pet_vaccinations (the SSOT) for vaccine checks.
Branch ticket/service-daycare off origin/main; squash-merge; migration for stays/capacity/report cards.
Gates: npm test + npm run test:integration.

GOAL: a facility sets capacity + vaccine requirements; owner books a stay (provides feeding/med
instructions); facility verifies required vaccines, checks the pet in/out, and posts daily report cards
the owner sees.

SCOPE
- Capacity/occupancy: per-location capacity; a stay holds a date range; prevent overbooking against
  capacity (extend 2.4 availability). 
- daycare_stays table (RLS'd): booking_id, pet_id, owner_user_id, provider_id, location_id, start/end,
  status (booked/checked_in/checked_out/cancelled), feeding_instructions, med_instructions,
  checked_in_at/out_at. Owner provides instructions at booking; facility updates check-in/out.
- Daily report cards: report_cards table (stay_id, date, mood, meals, activities, notes, photo/video
  urls[]) posted by facility staff, visible to the owner. Reuse Storage.
- Vaccine-requirement verification: facility configures required vaccines (per provider/location); at
  booking/check-in, verify the pet's pet_vaccinations cover them (needs owner consent grant of
  medical_read/vaccinations — OR have the OWNER's side surface their vax to the facility on booking;
  mirror the consent model, don't bypass assertCareAccess). Show pass/fail + missing vaccines.
- mobile: owner — book stay + instructions + see report cards + vaccine status; facility (web
  dashboard) — occupancy calendar, check-in/out, post report cards, vaccine check. Discovery
  ?type=daycare under Services → Daycare & Boarding.
- Tests: capability gate; capacity/overbook prevention; stay lifecycle; report cards owner-visible;
  vaccine check via consent; RLS on new tables.

DO NOT: bypass capability gate or assertCareAccess for vaccine reads; overbook; rebuild booking. No
fake data.

VERIFY: npm test + integration green. PR body: capacity, stays, report cards, consent-gated vaccine
check, RLS. Migration hand-applied after merge. Confirm origin/main.
```

# 2.84 — Business calendar import (external calendar → PawPi availability) (Wave 9)

**Status:** BUILT — CI-green. Migration **0064** (PENDING hand-apply). New env: `CRON_SECRET` +
external scheduler (flagged for Tats).

## Goal
The IMPORT half of calendar integration (Wave 8 did add-to-device + ICS export, one-way OUT). A
provider's existing Google/Outlook/Apple calendar should BLOCK their PawPi availability so they're
never double-booked. This is the CI-testable feed-import path — NOT device EventKit two-way sync.

## What shipped
- **Migration 0064** — `provider_calendar_feeds` (owner/admin FOR ALL + active-staff SELECT) and
  `provider_calendar_busy` (active-staff SELECT **only** — no write policy, so busy is READ-ONLY in
  PawPi). Both ENABLE+FORCE RLS. Four SECURITY DEFINER fns (pinned search_path, GRANT to pawpi_app):
  - `app_active_calendar_feeds()` — cron enumeration of active feeds.
  - `app_sync_calendar_feed(feed_id, events jsonb)` — the **only** busy writer: replaces a feed's
    busy rows + stamps `last_synced_at`.
  - `app_remove_calendar_feed(feed_id)` — soft-deletes the feed (history preserved) + clears its busy.
  - `app_provider_busy_windows(provider_id, from, to)` — the public availability/book subtract source
    (exposes only free/busy ranges; no event title/detail is ever stored).
- **ICS parsing** (`api/utils/calendarImport.js`, pure): `parseIcsBusy(ics)` → busy windows (UTC,
  all-day, DURATION, RFC-5545 line-folding); `fetchIcsFeed(url)` (timeout, fails soft → null). v1
  stores one block per VEVENT (no RRULE expansion — documented).
- **Routes:**
  - `GET/POST /api/providers/[id]/calendar-feeds` — list (staff) / add (owner|admin, http(s) URL).
  - `DELETE /api/providers/[id]/calendar-feeds/[feedId]` — remove → `app_remove_calendar_feed`.
  - `POST /api/providers/[id]/calendar-feeds/[feedId]/sync` — "Refresh now": fetch+parse+sync (soft).
  - `POST /api/providers/calendar/sync` — CRON_SECRET-guarded scheduler (mirrors 2.17): enumerate →
    fetch → parse → sync each; one bad feed fails soft.
- **Availability + booking respect busy:** the generalized-booking availability GET subtracts
  imported busy (via `app_provider_busy_windows`) alongside taken slots; the book route returns a
  clean **409** when a requested slot overlaps a busy block.
- **Web dashboard:** `/provider/calendar-import` (new sidebar entry) — add feed, Refresh now, see
  last-synced, remove.

## Mobile
Provider management is **web-primary** across the app (mobile onboarding hands off to the web
dashboard for services/locations/staff/calendar; see `vet-business-access.jsx`). Calendar feed
management lives on the web dashboard for the same reason — no separate mobile provider-settings
surface exists to extend. (Owners on mobile already finish business setup on the web dashboard.)

## Acceptance ✅
A mocked ICS yields busy blocks that make those slots unbookable (availability subtract +
`app_provider_busy_windows` overlap = the book-route 409 source); an invalid/unreachable URL fails
soft with a clean message; removing a feed clears its blocks (soft-delete, history preserved); RLS
proven (one provider can't read another's feed/busy; busy is read-only); web + integration tests green.

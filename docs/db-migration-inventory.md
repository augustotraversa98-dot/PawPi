## Anything silently dropping data or notifications **right now**?

I found **no unapplied migration that drops data or notifications on its own.** What I did find:

1. **Payment settlement (row 9) — the one real silent failure.** If a MercadoPago checkout is completed, the money can be taken and the app never learns. This is the item to fix before enabling real charges.
2. **0126 (row 3) — partial, latent exposure:** 12 notification-v2 helper functions are callable by `anon`/`authenticated` through the Data API (publishable key), several taking their subject as a parameter (e.g. `app_set_email_consent`, `app_record_push_ticket`). The table grants are already closed. Nothing in the app uses that path, but nothing stops a caller either. 0122 and 0123 are applied and verified, so the tag leak and the 500 on *Share clinic history* are gone.
3. **Notifications:** a static scan of the web code (every `safeNotify` / `app_notify` call) found **no emitted notification type that is missing from the latest `notifications_type_check` (0110)**, so no bell row is being rejected today. (`safeNotify` would swallow a rejection silently, which is why this was worth checking. The scan is a source scan, not a log query: if you want proof from production, search the Railway logs for `notifications_type_check`.) DMs / caregiver invites / walk invites send no notification **because the code never emits one** (F2-01/02/05), not because of a missing migration.

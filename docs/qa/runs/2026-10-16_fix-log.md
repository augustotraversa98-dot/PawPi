## Decisions made under the rules (no questions were asked)

1. **Black tab bar (10):** colour NOT changed. `pawpi-brand-kit/BRAND-GUIDELINES.md` has no pure black; approved alternatives are warm brown `#3B241B` and cream `#FFF7EF` (+ sand/peach/card/border). On iOS the bar is the *system* native glass tab bar (`NativeTabs`; the code sets no background colour on purpose), so the dark look in iPhone Mirroring is likely the OS material, not an app colour — **design decision needed**; verify on the phone first. Android's JS bar is already a cream/blur glass surface.
2. **Bottom clearance estimate:** the iOS tab-bar height is hard-coded as 56pt (`IOS_TAB_BAR_HEIGHT`) on top of the safe-area inset (no JS hook exposes the native bar height in expo-router 6 NativeTabs). Deliberately a little generous; tune after seeing it on device. Android (in-flow bar) and screens above the tab navigator (service/*, chat, modals — which cover the bar) are unchanged.
3. **Sticky-footer audit:** the other bottom CTAs (Add a dog, routine/appointment/photo-check modals, pickers) are React Native `Modal`s, which cover the tab bar → no change. Feed/Health/Care/Services/Profile-root already use `contentInsetAdjustmentBehavior="automatic"`.
4. **Log out (07):** kept the existing logout behaviour (clear account storage → welcome), only relabelled and added a confirm. Old `ownerMenu.resetApp` key's text left in the (shadowed duplicate) locale block; the live key is `ownerMenu.logOut`.
5. **Walk-tracking (12):** other "coming soon" strings in the locales are *different* features (quiet hours, map, monthly recap, AI summary, add photo…), not Apple Health/Watch — left alone. `healthKitIntegration.js` / post-walk source labels are data-driven and only reachable once a source exists — left.
6. **Version (02):** `expo-application` is not a dependency and adding it would change the npm-10 lockfile, so `expo-constants` is used (`nativeAppVersion`/`nativeBuildVersion` when exposed, else `expoConfig.version` / `ios.buildNumber`). With EAS remote versioning the build number may be absent → label shows `v1.0.2` only.
7. **Privacy (04) approach:** (a) usernames for NEW accounts come from the person's name or a random `pawpi_xxxxxx` handle — never the e-mail (4 creation sites, one helper); (b) API stops using `username` as a *display name* everywhere it was used as one (discover, pet-profile owner, followers list, feed posts/barks/daily update, day card, forum, lost & found, social walks, DMs, reviews, provider-side owner names, vet-record "added by", blocks list, notification actor); response field names were kept so the **already-shipped build 26 benefits without an app update** — those fields now carry the display name or `null`; (c) clients show the real name or a localized "Pet parent"/"Dueño/a", or hide the "by …" line; (d) regression guard test scans the API for `email.split("@")[0]` and `COALESCE(full_name, username)`. Also removed two e-mail leaks in vet-note author fallback (`staff_username`, acting user's e-mail).
   - **E-mail audit:** the only endpoint returning another person's e-mail is `adoption-applications` (applicant e-mail → that provider's owner/admin, already role-gated by audit A-23). Intentional; left.
   - Deliberately left (functional handles): `/api/search` owners match/return `username` and the Family & Caregivers invite, create-walk invitees, business staff invite and admin claims screens use `@username` as the invite handle; household leaderboard shows own-household usernames.
8. **🐾 emoji (08):** replaced only large standalone empty-state art with `PawMark` (coral): composer entry, empty feed, locked-feed card, "No barks yet" ×2. Left as decorative: "Dog Profile 🐾" menu/title, "Add a bark 🐾", milestone/share-card text, care-ring centre, forum author lines, welcome-back and generated notification/share copy, data icons (routines/general check/place reviews). The menu emoji icon set was left (not the logo).
9. **Welcome (09):** `welcome.jsx` renders "Forgot password?" unconditionally and `SocialSignInButtons` when `useSocialProviders` says Apple/Google are configured + supported. Not a code defect as far as can be told → recheck on the phone. No new auth flows built.
10. **Shorter copy (11):** the long telemetry blurb is removed from the row; "Learn more" opens the existing Privacy Policy URL and only renders when that URL is configured in the build (never a dead link). Locale JSON was edited as plain text (no round-trip), so intentional duplicate keys are untouched.
11. **Server-generated notification text:** paw/bark/follow bodies are English on the server; the app now renders localized text for those three types. Other server-sent bodies are still shown as sent.

## Decisions made under the rules (no questions were asked)

1. **Black tab bar (A):** the iOS bar is the *system* glass bar and the app has no dark theme (cream everywhere), so in phone dark mode the OS drew a *dark* glass bar under cream screens. Fix = pin the app to the light scheme on iOS (`Appearance.setColorScheme("light")`, JS-only/OTA-safe) + a light ultra-thin material for iOS < 26 (iOS 26 is never overridden) + brand `mutedBrown` for Android's inactive tint. This is effectively a "no dark mode" stance — a design call if you ever want real dark mode. Cause is inferred from code (no device).
2. **Handles (B):** reserved-word list is mine (admin, support, pawpi, …); the check endpoint answers only available/taken (+ free alternatives); network failure while checking = "unverified, allow save" because the server re-checks on save (409 with fresh alternatives). Add-another-dog sends no handle → server picks the first free candidate from the name.
3. **"Friend" (C):** `pet_friendships` has **no creation path anywhere in the app**, so an accepted-friendship picker would always be empty. Friend = accepted friendship **or mutual follow**; one-way follows excluded. Old typed `@handle` requests (build 26) still work but are held to the same rule.
4. **Backfill (D):** replacement name = display name → first pet's name → random `pawpi_xxxxxx`; unique case-insensitively vs usernames **and** pet handles + reserved list; never itself e-mail-shaped (idempotent). Audit copy **was** kept (`user_profile_username_backfill_audit`, RLS enabled + forced, owner-select only; covered by the RLS/DEFINER/Data-API guard tests) because it fits the migration rules; it holds e-mail-ish strings, so the runbook says to drop it after confirming. Merge is inert: the web deploy only builds/starts the app, `migrate.ts` is test-only.
5. **E-series scope:** only "route to the existing canonical component/token" fixes. I did **not** add a `COLORS.danger` token (picking the red is a brand decision), did not touch `#FFF`/the second "health palette"/`#F4A460`, fonts, button system, toasts, or sheet idiom (audit §5). `KeyboardSafeFormModal`'s off-palette green default → coral (only Edit-medical-profile used it).
6. **Date keys:** the ~35 `toISOString().split("T")[0]` in `reminderGenerator.js` are a locked reminder-id/dismissal-key scheme — deliberately not touched.
7. **F1:** OS notifications now use the reminder id as their identifier (replace instead of stack) + a petId-scoped sweep; "Care reminders"/quiet-hours not changed (do they stop *local* reminders? — product call, F1-08).
8. **F3:** owner can no longer self-complete or reschedule a *business* booking (409, friendly copy; app hides the button). **No "payments live" flag added** (F3-25): production already has MercadoPago keys and go-live is in progress, so a default-off switch would silently disable it.
9. **Client-visible server changes are additive/backward compatible with build 26:** new fields only, taken-handle `400 → 409` keeps the same `error` string field, new 403/404/409/429 only on calls that were previously bypassable.

Everything in Task 3 is behind the server flag `NOTIF_V2_ENABLED` (absent = off). With it off, production behaviour is
unchanged and no v2 table/column/function is queried; with it on but a migration missing, v2 queries run in a
savepoint + try/catch and fall back to today's behaviour. With it on: no push goes to an owner who disabled that
category, is in quiet hours, is over the daily cap or has an invalid token (proved against real Postgres in
`notifications-v2-owner-push.integration.test.ts`).

What changed because the flag exists: the weekly-digest and win-back endpoints now return `{"skipped":"disabled"}` and
do nothing until the flag is on (you asked for this). If something outside this repo already calls them, they go
quiet until you turn the flag on.

Two things I decided that you may want to change (details in `docs/notifications-v2-design.md`):
- Business (provider-facing) pushes get invalid-token handling, receipts and send-log rows, but not owner quiet hours or the daily cap.
- "Lost-pet alerts nearby" = followers of the pet (what `lost-reports` already notifies), max 100 phone pushes per activation. A real radius needs owner locations, which PawPi does not store.
